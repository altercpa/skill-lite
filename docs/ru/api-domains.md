# Паркованные домены

API паркованных доменов позволяет управлять доменами, припаркованными на хранилищах трекера: получать список, добавлять, запускать проверку статуса, удалять и привязывать домены к [потокам](api-flows.md). Домены используются как основной адрес ссылки потока и поддерживают IDN (интернационализированные доменные имена). Также API позволяет управлять файлами подтверждения, отдаваемыми в корне домена — небольшими текстовыми/разметочными файлами (например, файлами верификации поисковых систем или `ads.txt`), которые подтверждают владение доменом или содержат статические декларации, без необходимости разворачивать за припаркованным доменом реальный веб-сервер.

Каждый домен принадлежит либо конкретному пользователю (личный домен), либо команде в целом (командный домен). При работе с `scope=gang` API обслуживает исключительно командные домены — общие для всей команды. Личные домены участников команды в gang-scope недоступны. То же правило владения действует и для файлов подтверждения: владелец файла копируется от родительского домена в момент создания файла и в дальнейшем не меняется.

<a id="domainslist"></a>
## Список доменов

**URL вебмастера**: `https://domain.com/api/domains/list.json?id={token}`

**URL команды**: `https://domain.com/api/domains/list.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/domains/list.json?id={token}&scope=admin`

Функция возвращает список паркованных доменов с поддержкой фильтрации и пагинации. Все фильтры объединяются по условию AND. При `scope=admin` проверка биллинга не выполняется.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |
| `gang` | Для `scope=admin`: ID команды для фильтрации. |
| `flow` | Символьный код потока для фильтрации по привязке (формат `flow_code`, как в ответах [API потоков](api-flows.md)). |
| `fid` | Числовой идентификатор потока для фильтрации по привязке. |
| `url` | Подстрока для поиска по человекочитаемому имени домена. |
| `addr` | Подстрока для поиска по punycode-форме домена. |
| `ip` | IP-адрес для фильтрации по хосту домена. |
| `status` | Фильтр по статусу домена (см. ниже). |
| `uid` | Точный поиск по числовому идентификатору домена. |
| `page` | Страница результатов (≥ 1). По умолчанию — 1. |
| `show` | Размер страницы. По умолчанию — 0 (вернуть все записи без ограничения). |

Значения поля `status`:

- `0` — Ожидание (домен добавлен, проверка не выполнялась).
- `1` — Активен (HTTP-проверка прошла успешно).
- `2` — OK + SSL (HTTPS-проверка прошла успешно).
- `3` — Ошибка (домен не отвечает).
- `4` — Не туда (домен отвечает, но указывает на другой сервер).

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `total` | Общее количество записей, соответствующих фильтрам. При `show > 0` вычисляется отдельным запросом. |
| `page` | Текущая страница. |
| `show` | Размер страницы. |
| `data` | Словарь доменов, ключи — числовой идентификатор домена (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства (неверный scope, нет прав тимлида или администратора).
- `unpaid` — истёк или не оплачен доступ к трекеру (только для `scope=user` и `scope=gang`).

Состав записи в `data`:

| Поле | Описание |
| --- | --- |
| `uid` | Числовой идентификатор домена. |
| `url` | Человекочитаемое имя домена (IDN-декодированное). |
| `addr` | Punycode-форма доменного имени. |
| `ip` | IP-адрес, зафиксированный при последней проверке. |
| `user` | ID пользователя-владельца; `0` для командного домена. |
| `gang` | ID команды-владельца; `0` для личного домена. |
| `flow` | Числовой идентификатор привязанного потока; `0` — не привязан. |
| `status` | Статус домена (см. выше). |
| `stage` | Строковый статус: `wait`, `active`, `ok`, `error`, `wrong`. |
| `time` | Unix-время добавления домена. |
| `created` | Дата регистрации по WHOIS в формате `Ymd` (например, `20210914`). |
| `expires` | Дата истечения регистрации по WHOIS в формате `Ymd`. |
| `isok` | Статус делегирования по WHOIS: `0` — нет данных, `1` — делегирован, `2` — есть проблемы. |

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "total": 2,
    "page": 1,
    "show": 0,
    "data": {
        "42": {
            "uid": 42,
            "url": "пример.рф",
            "addr": "xn--e1afmkfd.xn--p1ai",
            "ip": "203.0.113.10",
            "user": 0,
            "gang": 3,
            "flow": 18,
            "status": 2,
            "stage": "ok",
            "time": 1714723200,
            "created": 20210914,
            "expires": 20260914,
            "isok": 1
        }
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "scope"
}
```

<a id="domainsadd"></a>
## Добавить домен

**URL вебмастера**: `https://domain.com/api/domains/add.json?id={token}`

**URL команды**: `https://domain.com/api/domains/add.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/domains/add.json?id={token}&scope=admin`

Функция добавляет один паркованный домен. Имя домена может быть передано с протоколом (`https://example.com`) или с префиксом `www.` — трекер автоматически нормализует его. Добавленный домен получает статус 0 (Ожидание); фактическая проверка запускается позднее — по расписанию CRON или явным вызовом [проверки домена](#domainscheck). При работе с `scope=gang` домен сразу создаётся как командный и принадлежит команде в целом, а не конкретному участнику.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `url`* | Доменное имя. Обязательный параметр. |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |
| `user` | Для `scope=admin` без `gang`: ID пользователя-владельца нового домена. |
| `gang` | Для `scope=admin`: ID команды-владельца нового домена. |

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные созданного домена (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства.
- `unpaid` — истёк или не оплачен доступ к трекеру (только для `scope=user` и `scope=gang`).
- `no-user` — для `scope=admin` не передан ни `user`, ни `gang`.
- `no-url` — параметр `url` не передан или пуст.
- `bad-url` — доменное имя после нормализации оказалось пустым.
- `duplicate` — домен с таким именем уже добавлен в систему.
- `bad-domain` — невозможно добавить домен: передан IP-адрес, системный домен трекера, имя не прошло валидацию IDNA или произошла ошибка базы данных.

Состав поля `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор созданного домена. |
| `user` | ID пользователя-владельца; `0` для командного домена. |
| `gang` | ID команды-владельца; `0` для личного домена. |
| `url` | Человекочитаемое имя домена. |
| `addr` | Punycode-форма доменного имени. |

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 137,
        "user": 0,
        "gang": 3,
        "url": "пример.рф",
        "addr": "xn--e1afmkfd.xn--p1ai"
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "duplicate"
}
```

<a id="domainscheck"></a>
## Проверка домена

**URL вебмастера**: `https://domain.com/api/domains/check.json?id={token}`

**URL команды**: `https://domain.com/api/domains/check.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/domains/check.json?id={token}&scope=admin`

Функция немедленно запускает проверку статуса домена и возвращает актуальные данные. В ходе проверки трекер отправляет HTTP- и HTTPS-запросы к домену и обновляет WHOIS-информацию. Ответ содержит состояние домена после завершения проверки.

Домен идентифицируется по `uid` (числовому идентификатору) либо по имени (`url` или `domain`). При отсутствии домена или нехватке прав по scope функция возвращает `not-found` без уточнения причины.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `uid` | Числовой идентификатор домена. |
| `url` | Имя домена. Используется, если `uid` не передан. |
| `domain` | Альтернативное поле для имени домена. Используется, если `uid` и `url` не переданы. |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |

Необходимо передать хотя бы одно из полей `uid`, `url` или `domain`.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные домена после проверки (состав полей — как в [списке доменов](#domainslist)). |

Коды ошибок:

- `not-found` — домен не найден, не передан идентификатор, или недостаточно прав по scope.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "uid": 42,
        "url": "пример.рф",
        "addr": "xn--e1afmkfd.xn--p1ai",
        "ip": "203.0.113.10",
        "user": 0,
        "gang": 3,
        "flow": 18,
        "status": 2,
        "stage": "ok",
        "time": 1714723200,
        "created": 20210914,
        "expires": 20260914,
        "isok": 1
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "not-found"
}
```

## Удалить домен

**URL вебмастера**: `https://domain.com/api/domains/del.json?id={token}`

**URL команды**: `https://domain.com/api/domains/del.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/domains/del.json?id={token}&scope=admin`

Функция удаляет домен из системы. Вместе с записью домена удаляются все связанные файлы (верификационные и прочие файлы в корне домена). Потоки, у которых этот домен был выбран как домен ссылки, теряют привязку к нему — рекомендуется заблаговременно обновить соответствующие [потоки](api-flows.md).

Домен идентифицируется по `uid` либо по имени (`url` или `domain`). При работе с `scope=gang` доступны только командные домены этой команды — личные домены участников недоступны.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `uid` | Числовой идентификатор домена. |
| `url` | Имя домена. Используется, если `uid` не передан. |
| `domain` | Альтернативное поле для имени домена. Используется, если `uid` и `url` не переданы. |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |

Необходимо передать хотя бы одно из полей `uid`, `url` или `domain`.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные удалённого домена (см. ниже). |

Коды ошибок:

- `not-found` — домен не найден, не передан идентификатор, или недостаточно прав по scope.
- `bad-domain` — не удалось удалить домен: ошибка базы данных или нарушение условий владения.

Состав поля `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор удалённого домена. |
| `user` | ID пользователя-владельца; `0` для командного домена. |
| `gang` | ID команды-владельца; `0` для личного домена. |
| `url` | Человекочитаемое имя домена. |
| `addr` | Punycode-форма доменного имени. |

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 42,
        "user": 0,
        "gang": 3,
        "url": "пример.рф",
        "addr": "xn--e1afmkfd.xn--p1ai"
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "not-found"
}
```

<a id="domainsglue"></a>
## Привязать домен к потоку

**URL вебмастера**: `https://domain.com/api/domains/glue.json?id={token}`

**URL команды**: `https://domain.com/api/domains/glue.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/domains/glue.json?id={token}&scope=admin`

Функция привязывает домен к потоку или отвязывает его. Поток указывается символьным кодом (`flow`) или числовым идентификатором (`fid`). Чтобы отвязать домен от потока, передайте `flow=0` или не передавайте ни `flow`, ни `fid`.

Поток должен принадлежать тому же владельцу, что и домен: при `scope=user` — тому же пользователю, при `scope=gang` — той же команде. Привязка к потоку другого владельца вернёт ошибку `glue`.

Домен идентифицируется по `uid` либо по имени (`url` или `domain`).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `uid` | Числовой идентификатор домена. |
| `url` | Имя домена. Используется, если `uid` не передан. |
| `domain` | Альтернативное поле для имени домена. Используется, если `uid` и `url` не переданы. |
| `flow` | Символьный код потока (например, `ef1c`). |
| `fid` | Числовой идентификатор потока. Используется, если `flow` не передан или не декодируется. |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |

Необходимо передать хотя бы одно из полей `uid`, `url` или `domain`.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные домена после привязки (см. ниже). |

Коды ошибок:

- `not-found` — домен не найден, не передан идентификатор, или недостаточно прав по scope.
- `glue` — не удалось выполнить привязку: поток принадлежит другому владельцу или ошибка базы данных.

Состав поля `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор домена. |
| `user` | ID пользователя-владельца; `0` для командного домена. |
| `gang` | ID команды-владельца; `0` для личного домена. |
| `url` | Человекочитаемое имя домена. |
| `addr` | Punycode-форма доменного имени. |
| `flow` | Числовой идентификатор привязанного потока; `0` при отвязке. |
| `code` | Символьный код привязанного потока; `false` при отвязке. |

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 42,
        "user": 0,
        "gang": 3,
        "url": "пример.рф",
        "addr": "xn--e1afmkfd.xn--p1ai",
        "flow": 18,
        "code": "ef1c"
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "glue"
}
```

<a id="domainsfiles"></a>
## Список файлов подтверждения

**URL вебмастера**: `https://domain.com/api/domains/files.json?id={token}`

**URL команды**: `https://domain.com/api/domains/files.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/domains/files.json?id={token}&scope=admin`

Функция возвращает все файлы подтверждения, хранящиеся в корне домена, вместе с их полным содержимым. Файл подтверждения — небольшой текстовый/разметочный файл (например, файл верификации поисковой системы или `ads.txt`), который отдаётся напрямую фронтендом трекера, когда запрос к припаркованному домену соответствует одиночному корневому пути с разрешённым расширением — реальный веб-сервер за доменом для этого не требуется. Пагинация отсутствует: всегда возвращается полный список файлов домена. В отличие от [списка доменов](#domainslist) и [добавления домена](#domainsadd), эта функция не проверяет статус биллинга.

Домен идентифицируется по `uid` либо по имени (`url` или `domain`) — так же, как в [проверке домена](#domainscheck), [удалении домена](#domainsdel) и [привязке домена к потоку](#domainsglue).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `uid` | Числовой идентификатор домена. |
| `url` | Имя домена. Используется, если `uid` не передан. |
| `domain` | Альтернативное поле для имени домена. Используется, если `uid` и `url` не переданы. |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |

Необходимо передать хотя бы одно из полей `uid`, `url` или `domain`.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |

Коды ошибок:

- `not-found` — домен не найден, не передан идентификатор, или недостаточно прав по scope.

Состав записи в `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор файла. |
| `dom` | Числовой идентификатор родительского домена. |
| `user` | ID пользователя-владельца; `0` для командного файла. |
| `gang` | ID команды-владельца; `0` для личного файла. |
| `name` | Имя файла в корне домена, например `ads.txt`. |

<a id="domainsconfirm"></a>
## Создать файл подтверждения

**URL вебмастера**: `https://domain.com/api/domains/confirm.json?id={token}`

**URL команды**: `https://domain.com/api/domains/confirm.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/domains/confirm.json?id={token}&scope=admin`

Функция создаёт файл подтверждения в корне домена. Поскольку имя файла уникально в пределах домена, повторный вызов с тем же `name` для того же домена молча перезаписывает содержимое существующего файла вместо ошибки дублирования — функция ведёт себя как upsert (создать или заменить). Эта функция не проверяет статус биллинга.

Домен (а не файл) идентифицируется по `uid` либо по имени (`url` или `domain`) — так же, как в [проверке домена](#domainscheck), [удалении домена](#domainsdel) и [привязке домена к потоку](#domainsglue).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `uid` | Числовой идентификатор домена. |
| `url` | Имя домена. Используется, если `uid` не передан. |
| `domain` | Альтернативное поле для имени домена. Используется, если `uid` и `url` не переданы. |
| `name`* | Имя файла в корне домена, например `ads.txt`, `google123.html`. Обязательный параметр. |
| `data` | Содержимое файла. По умолчанию — пустая строка. |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |

Необходимо передать хотя бы одно из полей `uid`, `url` или `domain`.

Перед использованием `name` очищается: удаляются все символы вне набора `[A-Za-z0-9._-]`, а ведущие и завершающие символы `.`, `-`, `_` обрезаются. Расширение (часть после последней точки, в нижнем регистре) должно быть одним из `txt`, `js`, `json`, `htm`, `html`, `css`, `xml` — любое другое расширение, а также имя, ставшее пустым после очистки, отклоняются. `data` обрезается по краям и усекается до 3500 символов; пустое содержимое допустимо.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные созданного или обновлённого файла (см. ниже). |

Коды ошибок:

- `not-found` — домен не найден, не передан идентификатор, или недостаточно прав по scope.
- `no-name` — параметр `name` не передан или пуст.
- `bad-file` — не удалось создать файл: недопустимое имя или расширение после очистки, либо ошибка базы данных.

Состав поля `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор файла. |
| `dom` | Числовой идентификатор родительского домена. |
| `user` | ID пользователя-владельца; `0` для командного файла. |
| `gang` | ID команды-владельца; `0` для личного файла. |
| `name` | Имя файла в корне домена. |
| `data` | Исходное содержимое файла (см. выше). |

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 8,
        "dom": 42,
        "user": 0,
        "gang": 3,
        "name": "google1234567890.html",
        "data": "google-site-verification: google1234567890.html"
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "bad-file"
}
```

<a id="domainschange"></a>
## Изменить файл подтверждения

**URL вебмастера**: `https://domain.com/api/domains/change.json?id={token}`

**URL команды**: `https://domain.com/api/domains/change.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/domains/change.json?id={token}&scope=admin`

Функция переименовывает и/или перезаписывает содержимое существующего файла подтверждения. В отличие от [создания файла подтверждения](#domainsconfirm), это обычное обновление, а не upsert: если новое `name` конфликтует с другим существующим файлом того же домена, вызов завершится ошибкой `bad-file`. Эта функция не проверяет статус биллинга.

Сам файл (а не родительский домен) идентифицируется напрямую по числовому идентификатору файла — через `fid` или `file` (альтернативное поле, проверяется вторым, если `fid` не передан). В отличие от [создания файла подтверждения](#domainsconfirm), здесь нет параметров `uid`/`url`/`domain`.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `fid` | Числовой идентификатор файла. |
| `file` | Альтернативное поле для числового идентификатора файла. Используется, если `fid` не передан. |
| `name`* | Новое имя файла в корне домена. Обязательный параметр. |
| `data` | Новое содержимое файла. По умолчанию — пустая строка. |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |

Необходимо передать хотя бы одно из полей `fid` или `file`. Поля `name` и `data` очищаются так же, как в [создании файла подтверждения](#domainsconfirm).

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные обновлённого файла (см. ниже). |

Коды ошибок:

- `not-found` — файл не найден, не передан идентификатор, или недостаточно прав по scope.
- `no-name` — параметр `name` не передан или пуст.
- `bad-file` — не удалось обновить файл: недопустимое имя или расширение после очистки, конфликт нового имени с другим файлом того же домена, либо ошибка базы данных.

Состав поля `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор файла. |
| `dom` | Числовой идентификатор родительского домена. |
| `user` | ID пользователя-владельца; `0` для командного файла. |
| `gang` | ID команды-владельца; `0` для личного файла. |
| `name` | Имя файла в корне домена (см. выше). |
| `data` | Исходное содержимое файла (см. выше). |

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 8,
        "dom": 42,
        "user": 0,
        "gang": 3,
        "name": "google1234567890.html",
        "data": "google-site-verification: google1234567890.html (updated)"
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "bad-file"
}
```

## Удалить файл подтверждения

**URL вебмастера**: `https://domain.com/api/domains/remove.json?id={token}`

**URL администратора**: `https://domain.com/api/domains/remove.json?id={token}&scope=admin`

Функция удаляет один файл подтверждения. В отличие от [удаления домена](#domainsdel), которое удаляет все файлы домена как побочный эффект, эта функция удаляет ровно один файл и не затрагивает домен и его остальные файлы. Эта функция не проверяет статус биллинга.

Файл идентифицируется напрямую по числовому идентификатору файла — через `fid` или `file` (альтернативное поле, проверяется вторым, если `fid` не передан) — так же, как в [изменении файла подтверждения](#domainschange).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `fid` | Числовой идентификатор файла. |
| `file` | Альтернативное поле для числового идентификатора файла. Используется, если `fid` не передан. |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |

Необходимо передать хотя бы одно из полей `fid` или `file`.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные удалённого файла (см. ниже). |

Коды ошибок:

- `not-found` — файл не найден, не передан идентификатор, или недостаточно прав по scope.
- `bad-file` — не удалось удалить файл: нарушение условий владения или ошибка базы данных.

Состав поля `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор файла. |
| `dom` | Числовой идентификатор родительского домена. |
| `user` | ID пользователя-владельца; `0` для командного файла. |
| `gang` | ID команды-владельца; `0` для личного файла. |
| `name` | Имя файла в корне домена. |

В отличие от других функций работы с файлами подтверждения, в этой записи нет подполя `data` с содержимым файла — удалённое содержимое в ответе не возвращается.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 8,
        "dom": 42,
        "user": 0,
        "gang": 3,
        "name": "google1234567890.html"
    }
```
