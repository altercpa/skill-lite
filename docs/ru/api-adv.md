# Коннекторы импорта расходов

API коннекторов импорта расходов управляет фоновыми интеграциями, которые периодически забирают статистику расходов из рекламных сетей и источников трафика (Facebook, TikTok, BIGO Ads, VK, MGid, LuckyAds, Dolphin, Dolphin Cloud, FBtool, MixAdvert, AdPartner) и записывают импортированную стоимость в клики трекера — туда же, куда пишет [ручной импорт расходов](api-tracker.md#spend), но автоматически, по расписанию. Каждая интеграция создаётся под один тип коннектора, выбираемый один раз и фиксируемый в дальнейшем; её реквизиты доступа, расписание и настройки, специфичные для коннектора, настраиваются отдельно.

Каждая интеграция принадлежит либо конкретному пользователю (личная интеграция), либо команде в целом (командная интеграция). Владение строго бинарно: в отличие от [хранилища сайтов](api-sites.md) или [паркованных доменов](api-domains.md), у командных интеграций нет маркера видимости на уровне участника — интеграция либо полностью личная, либо полностью командная.

<a id="advtypes"></a>
## Типы коннекторов

**URL вебмастера**: `https://domain.com/api/adv/types.json?id={token}`

**URL команды**: `https://domain.com/api/adv/types.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/adv/types.json?id={token}&scope=admin`

Функция возвращает каталог доступных типов коннекторов: код типа, используемый во всех остальных функциях этого API (`type`), вместе с его локализованным названием. Параметр `scope` влияет только на аутентификацию — возвращаемый каталог одинаков для любого вызывающего, независимо от scope.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Словарь типов коннекторов, ключи — код типа (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства (неверный scope, нет прав тимлида или администратора).

Словарь `data` сопоставляет каждому коду типа коннектора его локализованное название; записи упорядочены по алфавиту локализованного названия, а не по коду. Доступные коды типов:

- `facebook` — FB: Facebook
- `tiktok` — TikTok Ads
- `bigo` — BIGO Ads
- `dolphin` — FB: Dolphin
- `dolphincl` — FB: Dolphin Cloud
- `fbtool` — FB: FBtool
- `mgid` — MGid
- `mixadvert` — MixAdvert
- `adpartner` — AdPartner
- `luckyads` — LuckyAds
- `vk` — VK: ВКонтакте

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "adpartner": "AdPartner",
        "bigo": "BIGO Ads",
        "dolphin": "FB: Dolphin",
        "dolphincl": "FB: Dolphin Cloud",
        "facebook": "FB: Facebook",
        "fbtool": "FB: FBtool",
        "luckyads": "LuckyAds",
        "mgid": "MGid",
        "mixadvert": "MixAdvert",
        "tiktok": "TikTok Ads",
        "vk": "VK: VKontakte"
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "scope"
}
```

<a id="advtags"></a>
## Список меток для сопоставления расходов

**URL вебмастера**: `https://domain.com/api/adv/tags.json?id={token}`

**URL команды**: `https://domain.com/api/adv/tags.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/adv/tags.json?id={token}&scope=admin`

Функция возвращает упорядоченный список меток для селектора "в каком поле клика содержится ID объявления/креатива", используемого при отрисовке настройки `field` (`dataset.tags` в [форме редактирования интеграции](#advform)), без необходимости зашивать названия меток на стороне клиента. Как и в [типах коннекторов](#advtypes), `scope` влияет только на аутентификацию — возвращаемый список одинаков для любого вызывающего.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Словарь меток, ключи — целочисленный индекс, хранимый в `field` (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства.

Значения `data` (индекс — метка):

- `0` — `utm_content`
- `1` — `utm_term`
- `2` — `utm_medium`
- `3` — `utm_campaign`
- `4` — `utm_source`
- `5` — `domain`
- `6` — `subid`
- `7` — `flow`
- `8` — `way`
- `9` — `customer`

Каждый индекс выбирает, какое поле клика (UTM-метка, домен, SubID, поток, путь или клиент — согласно списку выше) сопоставляется с ID объявления/креатива при применении расходов.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "0": "utm_content", "1": "utm_term", "2": "utm_medium",
        "3": "utm_campaign", "4": "utm_source", "5": "domain",
        "6": "subid", "7": "flow", "8": "way", "9": "customer"
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "scope"
}
```

<a id="advlist"></a>
## Список интеграций

**URL вебмастера**: `https://domain.com/api/adv/list.json?id={token}`

**URL команды**: `https://domain.com/api/adv/list.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/adv/list.json?id={token}&scope=admin`

Функция возвращает список настроенных интеграций импорта расходов с поддержкой фильтрации и пагинации. Все фильтры объединяются по условию AND. Результаты упорядочены: сначала активные интеграции (по убыванию `status`), затем по алфавиту названия.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |
| `user` | Для `scope=admin`: ID конкретного пользователя для фильтрации. |
| `gang` | Для `scope=admin`: ID команды для фильтрации. |
| `type` | Фильтр по коду типа коннектора. Нераспознанный код молча игнорируется (фильтр не применяется). |
| `search` | Полнотекстовый поиск по названию интеграции. |
| `page` | Страница результатов (≥ 1). По умолчанию — 1. |
| `show` | Размер страницы. По умолчанию — 0 (вернуть все записи без ограничения). |

Для `scope=admin`, если не переданы ни `user`, ни `gang`, возвращаются все интеграции в системе.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `total` | Общее количество записей, соответствующих фильтрам. При `show > 0` вычисляется отдельным запросом. |
| `page` | Текущая страница. |
| `show` | Размер страницы. |
| `data` | Словарь интеграций, ключи — числовой идентификатор интеграции (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства (неверный scope, нет прав тимлида или администратора).

Состав записи в `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор интеграции. |
| `name` | Название интеграции. |
| `status` | Статус интеграции (см. ниже). |
| `type` | Код типа коннектора. |
| `typename` | Локализованное название коннектора, либо исходный код типа, если локализованного названия нет. |
| `last` | Unix-время последнего запуска по CRON; `0`, если запусков ещё не было. |
| `next` | Unix-время следующего запланированного запуска по CRON. |

Значения поля `status`:

- `0` — отключена (интеграция никогда не выбирается планировщиком CRON).
- `1` — активна.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "total": 1,
    "page": 1,
    "show": 0,
    "data": {
        "12": {
            "id": 12,
            "name": "FB main",
            "status": 1,
            "type": "facebook",
            "typename": "FB: Facebook",
            "last": 1752600000,
            "next": 1752610800
        }
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "scope"
}
```

<a id="advform"></a>
## Форма редактирования интеграции

**URL вебмастера**: `https://domain.com/api/adv/form.json?id={token}`

**URL команды**: `https://domain.com/api/adv/form.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/adv/form.json?id={token}&scope=admin`

Функция за один вызов возвращает всё необходимое для отрисовки полной формы редактирования интеграции: все сохранённые поля, собственные дескрипторы дополнительных полей коннектора и справочные данные (`dataset`) для заполнения селектов формы.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |
| `adv`* | Идентификатор интеграции. Обязательный параметр. |

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные интеграции и дескрипторы полей, специфичных для коннектора (см. ниже). |
| `dataset` | Справочные данные для отрисовки формы (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства.
- `no-id` — параметр `adv` не передан (или равен `0`).
- `not-found` — интеграция с таким идентификатором не найдена, либо её тип коннектора больше не доступен.
- `access` — интеграция не принадлежит вызывающему в рамках разрешённого scope.

Состав поля `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор интеграции. |
| `type` | Код типа коннектора. Фиксируется при создании, дальнейшему изменению не подлежит. |
| `typename` | Локализованное название коннектора. |
| `status` | Статус интеграции: `1` — активна, `0` — отключена. |
| `name` | Название интеграции. |
| `url` | Стандартный реквизит доступа: URL. Имеет значение, только если присутствует в `dataset.auths`. |
| `login` | Стандартный реквизит доступа: логин. Имеет значение, только если присутствует в `dataset.auths`. |
| `pass` | Стандартный реквизит доступа: пароль. Имеет значение, только если присутствует в `dataset.auths`. |
| `user` | Стандартный реквизит доступа: идентификатор пользователя/аккаунта. Имеет значение, только если присутствует в `dataset.auths`. |
| `api` | Стандартный реквизит доступа: API-ключ. Имеет значение, только если присутствует в `dataset.auths`. |
| `key` | Стандартный реквизит доступа: API-секрет. Имеет значение, только если присутствует в `dataset.auths`. |
| `repeat` | Частота проверки (см. ниже). |
| `period` | Период отчёта, забираемый при каждом запуске (см. ниже). |
| `unique` | `1` — учитывать при сопоставлении расходов только уникальные клики; `0` — учитывать все. |
| `valid` | `1` — учитывать при сопоставлении расходов только целевые (непрофильтрованные) клики; `0` — учитывать все. |
| `source` | Необязательный фильтр по значению `utm_source`; пусто — фильтр не применяется. |
| `field` | В каком поле клика содержится ID объявления/креатива для сопоставления (см. [список меток для сопоставления расходов](#advtags)). |
| `meta` | Настройки, специфичные для коннектора, в декодированном виде (объект, а не сырая JSON-строка). |
| `fields` | Дескрипторы дополнительных полей коннектора для отрисовки настроек (см. ниже); пустой массив для коннекторов без дополнительных настроек. |

Все 6 стандартных реквизитов доступа (`url`, `login`, `pass`, `user`, `api`, `key`) всегда присутствуют в ответе независимо от того, какие из них реально использует коннектор — какие именно значимы для данного типа коннектора, показывает `dataset.auths`.

Значения `repeat` (частота проверки):

- `0` — Раз в день
- `1` — Каждый час
- `2` — Раз в три часа
- `3` — Дважды в день
- `4` — Трижды в день
- `5` — Раз в три дня

Значения `period` (период отчёта):

- `0` — Текущий день
- `1` — Вчерашний день
- `2` — Сегодня и вчера
- `3` — Три дня
- `4` — Неделя

Для всех значений, кроме `1` (только вчера), фактически забираемый диапазон дат дополнительно включает текущий день — например, `3` ("Три дня") на деле охватывает последние три дня плюс сегодня.

Каждый элемент `fields` описывает одну настройку, специфичную для коннектора:

| Поле | Описание |
| --- | --- |
| `type` | Тип поля ввода: `text`, `textarea`, `select` или `checkbox`. |
| `name` | Имя параметра для передачи обратно через [изменение интеграции](#advedit). |
| `head` | Человекочитаемое название. |
| `descr` | Необязательный поясняющий текст; отсутствует, если коннектор его не предоставляет. |
| `value` | Текущее значение, прочитанное из `meta`. |
| `options` | Только для `type=select`: список подписей вариантов, индекс массива — значение для передачи. |

Состав `dataset`:

| Поле | Описание |
| --- | --- |
| `auths` | Список стандартных реквизитов доступа коннектора (подмножество `url`, `user`, `login`, `pass`, `api`, `key`) — какие из 6 реквизитов в `data` реально используются данным типом коннектора. |
| `tags` | Тот же список меток, что и в [списке меток для сопоставления расходов](#advtags). |
| `repeats` | Тот же список подписей, что и значения `repeat` выше, с тем же порядком индексов. |
| `periods` | Тот же список подписей, что и значения `period` выше, с тем же порядком индексов. |

Справочник коннекторов (код типа, локализованное название, используемые стандартные реквизиты, специфичные поля `fields`):

- `facebook` — FB: Facebook. Реквизиты: `api`. Поля: `facebook_mode` (select), `facebook_proxy` (text), `facebook_pauth` (text).
- `tiktok` — TikTok Ads. Реквизиты: `api`. Поля: `tiktok_mode` (select), `tiktok_accs` (text, ID рекламодателей через запятую), `tiktok_proxy` (text), `tiktok_pauth` (text).
- `bigo` — BIGO Ads. Реквизиты: `api`, `key`. Поля: `bigo_refresh` (textarea, исходный OAuth refresh token), `bigo_mode` (select).
- `dolphin` — FB: Dolphin. Реквизиты: `url`, `api`. Поля: `dolphin_type` (select), `dolphin_cur` (select, код валюты).
- `dolphincl` — FB: Dolphin Cloud. Реквизиты: `api`. Поля: `dolphin_type` (select), `dolphin_cur` (select).
- `fbtool` — FB: FBtool. Реквизиты: `api`. Поля: `fbtool_mode` (select), `fbtool_ast` (select, фильтр по статусу кампании), `fbtool_accs` (text).
- `mgid` — MGid. Реквизиты: `login`, `pass`. Без специфичных полей.
- `mixadvert` — MixAdvert. Реквизиты: `login`, `api`. Поля: `mixadvert_mode` (select).
- `adpartner` — AdPartner. Реквизиты: `api`. Без специфичных полей.
- `luckyads` — LuckyAds. Реквизиты: `api`. Поля: `luckyads_mode` (select), `luckyads_cur` (select).
- `vk` — VK: ВКонтакте. Реквизиты: `login`, `key`. Поля: `vk_mode` (select), `vk_reset` (checkbox, автоматическое удаление устаревших OAuth-токенов).

Для коннектора `bigo` OAuth-токен доступа, срок его действия и — если BIGO ротирует его — новый refresh-токен, хранящиеся в `meta`, могут быть незаметно перезаписаны самим запланированным запуском (ротация токена), независимо от вызова [изменения интеграции](#advedit). Клиент, опрашивающий эту функцию, может увидеть изменение `meta` между вызовами без собственного вызова редактирования; повторная передача текущего значения `bigo_refresh` при [изменении](#advedit) сохраняет это ротированное состояние, а действительно новое значение его заменяет.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 12, "type": "facebook", "typename": "FB: Facebook",
        "status": 1, "name": "FB main",
        "url": "", "login": "", "pass": "", "user": "", "api": "EAAB...", "key": "",
        "repeat": 4, "period": 1, "unique": 1, "valid": 1,
        "source": "", "field": 0,
        "meta": { "mode": 0, "proxy": "", "pauth": "" },
        "fields": [
            { "type": "select", "name": "facebook_mode", "head": "Contains", "value": 0, "options": [ "ID of ad", "ID of adset", "ID of campaign" ] },
            { "type": "text", "name": "facebook_proxy", "head": "Proxy for requests", "descr": "Protocol, IP address and port, e.g.: socks5://1.2.3.4:56", "value": "" },
            { "type": "text", "name": "facebook_pauth", "head": "Proxy authorization", "descr": "Login and password separated by a colon, e.g.: user:pass", "value": "" }
        ]
    },
    "dataset": {
        "auths": [ "api" ],
        "tags": { "0": "utm_content", "1": "utm_term", "2": "utm_medium", "3": "utm_campaign", "4": "utm_source", "5": "domain", "6": "subid", "7": "flow", "8": "way", "9": "customer" },
        "repeats": [ "Once a day", "Each hour", "Once 3 hours", "Twice a day", "3 times per day", "Once 3 days" ],
        "periods": [ "Today", "Yesterday", "Today and yesterday", "3 days", "1 week" ]
    }
```

<a id="advadd"></a>
## Создать интеграцию

**URL вебмастера**: `https://domain.com/api/adv/add.json?id={token}`

**URL команды**: `https://domain.com/api/adv/add.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/adv/add.json?id={token}&scope=admin`

Функция создаёт заготовку новой интеграции — задаются только тип коннектора и название. Реквизиты доступа, расписание и настройки, специфичные для коннектора, должны быть заданы позже через [изменение интеграции](#advedit); рекомендуется сначала вызвать [форму редактирования интеграции](#advform), чтобы узнать, какие реквизиты доступа и специфичные настройки актуальны для выбранного типа.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `type`* | Код типа коннектора (см. [типы коннекторов](#advtypes)). Обязательный параметр. |
| `name` | Название интеграции. Фактически обязателен — пустое название сохраняется, но не несёт смысла. |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |
| `user` | Для `scope=admin` без `gang`: ID пользователя-владельца новой интеграции. |
| `gang` | Для `scope=admin`: ID команды-владельца новой интеграции. |

Для `scope=gang` владельцем всегда становится собственная команда вызывающего — параметр `gang` для не-административных scope не используется.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные созданной интеграции (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства.
- `bad-type` — `type` пуст или не является распознанным кодом коннектора.
- `no-user` — для `scope=admin` не передан ни `user`, ни `gang`.
- `db` — ошибка базы данных при создании интеграции.

Состав поля `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор созданной интеграции. |
| `type` | Код типа коннектора (см. выше). |
| `name` | Название интеграции (см. выше). |

Новые интеграции создаются отключёнными (`status` = `0`) — планировщик CRON выбирает только активные интеграции, поэтому только что созданная интеграция не будет запускаться, пока [изменение интеграции](#advedit) не установит `status=1`.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 42,
        "type": "facebook",
        "name": "FB main"
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "bad-type"
}
```

<a id="advedit"></a>
## Изменить интеграцию

**URL вебмастера**: `https://domain.com/api/adv/edit.json?id={token}`

**URL команды**: `https://domain.com/api/adv/edit.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/adv/edit.json?id={token}&scope=admin`

Функция обновляет любое подмножество стандартных полей интеграции (включая активацию через `status`) и/или её настройки, специфичные для коннектора. Все параметры необязательны — записываются только те, что фактически присутствуют в запросе; явное значение `0` или пустая строка всё равно считаются "присутствующими". Если в запросе не оказалось ни одного распознанного поля, функция ничего не делает и возвращает `status: ok` с текущими, неизменными данными интеграции.

**Настройки коннектора обновляются по принципу "всё или ничего".** Если в запросе присутствует хотя бы одно из собственных имён полей коннектора (перечисленных в `data.fields` из [формы редактирования интеграции](#advform)), коннектор полностью пересобирает блок настроек (`meta`) из запроса — без слияния с ранее сохранёнными значениями. На практике, если передать только одно из нескольких полей коннектора (например, только `facebook_mode` без `facebook_proxy`/`facebook_pauth`), пропущенные настройки будут сброшены в пустую строку. Чтобы изменить одну настройку коннектора, не сбрасывая остальные, нужно повторно передать полный набор полей коннектора, как он возвращён [формой редактирования интеграции](#advform).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `adv`* | Идентификатор интеграции. Обязательный параметр. |
| `status` | Флаг активации: любое истинное значение активирует интеграцию, ложное — отключает. |
| `name` | Название интеграции. |
| `url` | Стандартный реквизит доступа: URL. |
| `login` | Стандартный реквизит доступа: логин. |
| `pass` | Стандартный реквизит доступа: пароль. |
| `user` | Стандартный реквизит доступа: идентификатор пользователя/аккаунта. |
| `api` | Стандартный реквизит доступа: API-ключ. |
| `key` | Стандартный реквизит доступа: API-секрет. |
| `period` | Период отчёта (см. выше). |
| `repeat` | Частота проверки (см. выше). |
| `unique` | `1` — учитывать при сопоставлении расходов только уникальные клики. |
| `valid` | `1` — учитывать при сопоставлении расходов только целевые (непрофильтрованные) клики. |
| `source` | Необязательный фильтр по значению `utm_source`. |
| `field` | В каком поле клика содержится ID объявления/креатива (см. [список меток для сопоставления расходов](#advtags)). |
| *(специфичные поля коннектора, например `facebook_mode`)* | Любое имя поля, объявленное коннектором в `data.fields` (см. [форму редактирования интеграции](#advform)); см. примечание выше о поведении "всё или ничего". |

`type` изменить после создания нельзя — передача этого параметра не имеет эффекта. `status` одновременно служит переключателем активации/деактивации; отдельной функции переключения не предусмотрено.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Данные интеграции после обновления (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства.
- `no-id` — параметр `adv` не передан (или равен `0`).
- `not-found` — интеграция с таким идентификатором не найдена, либо её тип коннектора больше не доступен.
- `access` — интеграция не принадлежит вызывающему в рамках разрешённого scope.
- `db` — ошибка базы данных при сохранении изменений.

Состав поля `data`: такой же, как `data` в [форме редактирования интеграции](#advform), но без ключа `fields` (обновлённый список дескрипторов полей коннектора не возвращается после изменения настроек — вызовите [форму редактирования интеграции](#advform) повторно, чтобы его получить).

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 12, "type": "facebook", "typename": "FB: Facebook",
        "status": 1, "name": "FB main",
        "url": "", "login": "", "pass": "", "user": "", "api": "EAAB...", "key": "",
        "repeat": 4, "period": 1, "unique": 1, "valid": 1,
        "source": "", "field": 0,
        "meta": { "mode": 0, "proxy": "", "pauth": "" }
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "access"
}
```

Функция сбрасывает время следующего запуска интеграции на текущее, чтобы планировщик CRON подхватил её на ближайшем тике, не дожидаясь настроенной частоты проверки (`repeat`).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |

| `error` | Код ошибки для статуса `error` (см. ниже). |
| `data` | Обновлённые данные расписания (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства.

Состав поля `data`:

Если интеграция отключена, принудительный сброс `next` на текущее время её не активирует — планировщик CRON выбирает только активные интеграции, независимо от времени следующего запуска. Если интеграция отключена, сначала установите `status=1` через [изменение интеграции](#advedit).

## Журнал запросов интеграции

**URL вебмастера**: `https://domain.com/api/adv/log.json?id={token}`

**URL команды**: `https://domain.com/api/adv/log.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/adv/log.json?id={token}&scope=admin`

Функция возвращает журнал исходящих HTTP-запросов, выполненных коннекторами, для диагностики интеграции. Результаты упорядочены от новых к старым.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `scope` | Рабочее пространство: `user` (по умолчанию), `gang`/`team`, `admin`/`sys`. |
| `user` | Для `scope=admin`: ID конкретного пользователя для фильтрации. |
| `gang` | Для `scope=admin`: ID команды для фильтрации. |
| `adv` | Ограничить журнал одной интеграцией по идентификатору. Если не передан, возвращается журнал всех интеграций, принадлежащих вызывающему в рамках разрешённого scope. |
| `error` | Фильтр по результату запроса (см. ниже). Если не передан, фильтр не применяется. |
| `page` | Страница результатов (≥ 1). По умолчанию — 1. |
| `show` | Размер страницы. По умолчанию — 0 (вернуть все записи без ограничения). |

Значения `error` (параметр фильтрации): любое истинное значение (например, `1`) ограничивает журнал неуспешными запросами; `0` (передан, но ложен) ограничивает журнал успешными запросами; при отсутствии параметра фильтр не применяется.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `total` | Общее количество записей журнала, соответствующих фильтрам. При `show > 0` вычисляется отдельным запросом. |
| `page` | Текущая страница. |
| `show` | Размер страницы. |
| `data` | Словарь записей журнала, ключи — числовой идентификатор записи (см. ниже). |

Коды ошибок:

- `scope` — не пройдена проверка прав рабочего пространства.

Состав записи в `data`:

| Поле | Описание |
| --- | --- |
| `id` | Числовой идентификатор записи журнала. |
| `adv` | Идентификатор интеграции, выполнившей запрос. |
| `time` | Unix-время запроса. |
| `url` | Полный URL запроса, без усечения. |
| `post` | Сырое тело POST-запроса, если оно было. |
| `reply` | Сырое тело ответа HTTP. |
| `cc` | JSON-конфигурация cURL-запроса (заголовки, прокси и т. д.). |
| `error` | `1`, если тело ответа было пустым (запрос считается неуспешным), иначе `0`. |
| `status` | HTTP-статус исходящего запроса; `0`, если сам запрос не удалось выполнить. |
| `timer` | Длительность запроса в секундах. |

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "total": 1,
    "page": 1,
    "show": 0,
    "data": {
        "501": {
            "id": 501,
            "adv": 12,
            "time": 1752610801,
            "url": "https://graph.facebook.com/v25.0/me/adaccounts?...",
            "post": "",
            "reply": "{\"data\":[...]}",
            "cc": "{\"verbose\":true}",
            "error": 0,
            "status": 200,
            "timer": 0.842
        }
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "scope"
}
```
