# Чёрные списки

Раздел API `blacklist` управляет **чёрными списками** фильтрации трафика: именованными списками блокируемых IPv4-адресов, IPv4-подсетей, IPv6-подсетей и правил для заголовков запроса. По этим спискам проверяется каждый визит, проходящий через фильтр клоаки или фильтр потоков трекера. С помощью API вы можете создавать, настраивать и удалять списки, добавлять, изменять и удалять их записи по одной, импортировать и экспортировать записи в виде CSV-файлов, а также узнавать, какие списки можно подключить к кампании фильтрации. Те же списки управляются в веб-интерфейсе в разделах "Мои фильтры", "Фильтры команды" и (для администраторов) "Фильтры трафика"; смысл полей записей также описан в руководстве пользователя [Чёрные списки](blacklist.md).

Список относится к одному из четырёх видов, который выбирается при создании списка и не может быть изменён позднее: IPv4-адреса, IPv4-подсети, IPv6-подсети или заголовки запроса (см. [Виды списков](#blacklisttypes)). Запись списка — это отдельный адрес, подсеть или правило для заголовка соответствующего вида.

Формат запросов: параметры читаются из строки запроса и из тела POST (форма или JSON); значение из тела имеет приоритет. Параметр `scope` читается только из строки запроса, даже если сам запрос отправляется методом POST. Только функция `import` требует `multipart/form-data`, а `export` возвращает CSV-файл вместо JSON. Идентификаторы записей, списков и кампаний — обычные целые числа.

Ответ с ошибкой всегда имеет вид `{"status": "error", "error": "<код>"}`; отказы по настройкам зеркала функции [edit](#blacklistedit) дополнительно содержат поле `message` с локализованным пояснением. Все коды ошибок собраны в разделе [Ошибки](#blacklisterrors), числовые ограничения — в разделе [Ограничения](#blacklistlimits).

<a id="blacklistfilter"></a>
## Как списки участвуют в фильтрации

- Кампания фильтрации (см. [Фильтрация трафика](api-filter.md)) проверяет визиты по спискам, выбранным в её поле `list`. Если ни один список не выбран, кампания использует все активные списки по умолчанию: системные, собственные списки владельца и списки его команды. Фильтр потоков трекера использует только списки по умолчанию видов IP-адреса, IP-подсети и IPv6-адреса; списки заголовков он не использует.
- Выбирать в кампании и использовать как списки по умолчанию можно только активные списки.
- Добавленные записи начинают работать сразу. Единственная задержка — у списков вида IP-подсети: поиск по подсетям кэшируется на 666 секунд (около 11 минут) для каждого блока /24, поэтому свежедобавленная подсеть может начать действовать для недавно проверенных адресов лишь через это время.
- Один адрес или правило для заголовка можно добавить и упрощённой функцией [Заблокировать IP или заголовок](api-filter.md#filterblock); функции этого раздела — её полный аналог для управления списками.

<a id="blacklistscopes"></a>
## Пространства и владельцы списков

Каждая функция работает в одном из трёх пространств, выбираемых параметром `scope` (см. [API-интерфейс](api.md)). Пространство определяет, какие списки видит функция и где создаются новые списки.

| Пространство | Описание |
| --- | --- |
| `scope=user` | По умолчанию. Ваши персональные списки ("Мои фильтры"). Доступно всем активным пользователям. Новые списки создаются как ваши персональные: активными и не по умолчанию. |
| `scope=gang` | Псевдоним: `team`. Общие списки вашей команды ("Фильтры команды"). Доступно только лидерам команды, даже если в веб-интерфейсе включён общий доступ к спискам команды для всех участников. Необязательный параметр `user` должен быть участником вашей команды, иначе возвращается ошибка `scope`; он имеет значение только для функции [avail](#blacklistavail). Новые списки создаются как списки команды: активными и не по умолчанию. |
| `scope=admin` | Только для администраторов. Без `gang` и `user` функция работает с глобальными списками (системные списки, включая автоматически обновляемые списки поставщиков; "Фильтры трафика"). С `gang` — со списками этой команды, с `user` — с персональными списками этого пользователя; если переданы оба параметра, приоритет у команды. Новые списки создаются в том же пространстве. |

Дополнительные параметры выбора пространства:

| Поле | Описание |
| --- | --- |
| `gang` | Только для пространства `admin`: ID команды. Должен быть числом, иначе возвращается `bad-gang`; функции [avail](#blacklistavail) и [add](#blacklistadd) дополнительно проверяют, что команда существует. |
| `user` | Пространство `admin`: ID пользователя. Должен быть числом, иначе возвращается `bad-user`; функции [avail](#blacklistavail) и [add](#blacklistadd) дополнительно проверяют, что пользователь существует. Пространство команды: см. выше. |
| `uu` | Только для ключей администраторов: ID пользователя, от имени которого выполняется запрос. Например, `scope=user&uu=123` работает с персональными списками пользователя 123. |

Примечания:

- Обычный пользователь не может читать и изменять глобальные (системные) списки функциями [list](#blacklistlist), [show](#blacklistshow) и [edit](#blacklistedit); в режиме чтения такие списки доступны ему только через [avail](#blacklistavail).
- Список, созданный в пространстве `admin` без `gang` и `user`, является **глобальным**. В отличие от персональных и командных списков он создаётся **неактивным** и **не по умолчанию**: активируйте его функцией [edit](#blacklistedit) (`status=1`), иначе он не будет предлагаться в кампаниях.
- Функции с параметром `list` работают только со списками выбранного пространства: список другого владельца сообщается как `bad-list`.

<a id="blacklistdict"></a>
## Справочные значения

Приведённые ниже значения используются несколькими функциями этого раздела.

<a id="blacklisttypes"></a>
### Виды списков

Вид списка передаётся в параметре `type` функций [add](#blacklistadd) и [list](#blacklistlist) и возвращается в поле `type` списка:

- `1` — IP-адреса: отдельные IPv4-адреса.
- `2` — IP-подсети: IPv4-подсети с длиной префикса от 8 до 31.
- `3` — IPv6-адреса: IPv6-подсети с длиной префикса от 32 до 128 (отдельный адрес — это подсеть размера 128).
- `4` — Заголовки: правила для значений заголовков запроса.

> **Внимание!** Параметр `type` имеет два разных значения. В функциях [add](#blacklistadd) и [list](#blacklistlist) это **вид списка** (1–4). В функциях [show](#blacklistshow), [block](#blacklistblock) и [change](#blacklistchange) это **идентификатор заголовка** записи списка заголовков (см. [Идентификаторы заголовков](#blacklistheaders)).

<a id="blacklistcomments"></a>
### Коды причин

Поле `comment` записи — число от 0 до 255, поясняющее причину блокировки. Интерфейс знает следующие причины:

- `1` — Публичный список
- `2` — Подозрительный
- `3` — Корпоративный
- `4` — Разные User-Agent
- `5` — Ошибочное ГЕО
- `6` — Ошибки заголовков
- `7` — Много ошибок
- `8` — Ошибочный запрос
- `9` — Бот

Значение `0` означает отсутствие причины. Функция `show` возвращает локализованные названия в `dataset.comments`.

<a id="blacklistavail"></a>
## Доступные списки

**URL вебмастера**: `https://domain.com/api/blacklist/avail.json?id={token}`

**URL команды**: `https://domain.com/api/blacklist/avail.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/blacklist/avail.json?id={token}&scope=admin`

**Метод**: `GET` или `POST`.

Возвращает списки, которые владелец кампании фильтрации может подключить к ней: сначала активные системные списки, затем активные персональные списки владельца, затем активные списки команды владельца; каждая группа отсортирована по названию. Неактивные списки не возвращаются никогда. Для каждого списка функция сообщает, является ли он списком по умолчанию и, если указана кампания, выбран ли он уже в этой кампании. Это данные селектора "Наборы фильтров" на экране кампании.

Это единственная функция, через которую обычный пользователь видит системные списки (название, вид и флаги, только для чтения).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `uid` | ID кампании фильтрации (см. [Настройка кампании](api-filter.md#filterset)). Если параметр передан, кампания должна существовать в текущем пространстве, иначе возвращается `no-site`. Владелец кампании становится владельцем списков, а флаги `selected` показывают выбор в кампании. Если параметр не передан, владелец определяется так, как описано для `user`, а `selected` всегда `false`. |
| `gang` | Только для пространства `admin`: ID команды. Команда должна существовать (иначе `bad-gang`). Ограничивает поиск кампании кампаниями участников команды. |
| `user` | Пространство `admin`: ID существующего пользователя (иначе `bad-user`). Пространство команды: ID участника команды. Без `uid` выбирает владельца списков и обязателен в пространствах команды и администратора (иначе `no-user`); в пространстве вебмастера владельцем является владелец ключа. С `uid` ограничивает поиск кампании кампаниями этого пользователя. |

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `data` | Ассоциативный массив предлагаемых списков, где ключ — ID списка. Состав описан ниже. |
| `dataset` | Дополнительные данные. Содержит поле `types`: код вида → локализованное название вида (см. [Виды списков](#blacklisttypes)). |

Коды ошибок:

- `scope` — пространство не определено или у вас нет прав на него.
- `bad-gang` — `gang` не является числом или команда не существует.
- `bad-user` — `user` не является числом или пользователь не существует.
- `no-site` — кампания `uid` не найдена в текущем пространстве.
- `no-user` — `uid` не передан и владелец списков не определён (нет `user`).

Состав элемента `data`:

| Поле | Описание |
| --- | --- |
| `id` | ID списка. |
| `name` | Название списка. |
| `type` | Вид списка (см. [Виды списков](#blacklisttypes)). |
| `role` | Вид владельца списка: `feed` — список поставщика, обновляется автоматически, `team` — список команды, `user` — персональный список, `admin` — глобальный список, управляемый вручную. |
| `default` | `true`, если список является списком по умолчанию для этого владельца. |
| `selected` | `true`, если список выбран в кампании `uid`. Неактивный список, сохранённый в кампании, не сообщается. |

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "3": {
            "id": 3,
            "name": "AlterCPA Lite IPv4",
            "type": 1,
            "role": "feed",
            "default": true,
            "selected": false
        },
        "12": {
            "id": 12,
            "name": "My proxies",
            "type": 2,
            "role": "user",
            "default": false,
            "selected": true
        }
    },
    "dataset": {
        "types": {
            "1": "IP addresses",
            "2": "IP networks",
            "3": "IPv6 addresses",
            "4": "Headers"
        }
    }
}
```

**Пример ответа сервера с ошибкой:**

```json
{
    "status": "error",
    "error": "no-site"
}
```

<a id="blacklistlist"></a>
## Список чёрных списков

**URL вебмастера**: `https://domain.com/api/blacklist/list.json?id={token}`

**URL команды**: `https://domain.com/api/blacklist/list.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/blacklist/list.json?id={token}&scope=admin`

**Метод**: `GET` или `POST`.

Возвращает чёрные списки текущего пространства с их настройками: сначала активные; внутри каждой группы списки отсортированы по названию. В пространстве `admin` без `gang` и `user` функция возвращает глобальные списки, включая списки поставщиков (см. [Пространства и владельцы списков](#blacklistscopes)).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `type` | Фильтр по виду списка, от 1 до 4 (см. [Виды списков](#blacklisttypes)). По умолчанию возвращаются списки всех видов. Любое другое значение возвращает `bad-type`. |
| `search` | Поиск по названию списка. Текст разбивается на слова по пробелам и запятым; слова короче 2 символов игнорируются. Список возвращается, только если его название содержит все слова (без учёта регистра). Если слов не осталось, поиск не применяется. |
| `page` | Номер страницы, начиная с 1. По умолчанию 1. |
| `show` | Количество списков на странице, от 0 до 1000. По умолчанию 0: все списки возвращаются сразу, без постраничной разбивки и без поля `nav`. Страница за пределами последней возвращает пустой `data`. |
| `gang` | Только для пространства `admin`: вернуть списки этой команды. |
| `user` | Только для пространства `admin`: вернуть персональные списки этого пользователя. |

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `data` | Ассоциативный массив списков, где ключ — ID списка. Состав описан ниже. Пустой результат возвращается как пустой массив. |
| `nav` | Данные постраничной навигации, возвращаются только при `show` больше 0: `total` — общее количество подходящих списков, `page` — текущая страница, `pages` — количество страниц, `show` — размер страницы. |
| `dataset` | Дополнительные данные: `types` — код вида → локализованное название вида, `periods` — период обновления в секундах → локализованное название (все поддерживаемые периоды). |

Коды ошибок:

- `scope` — пространство не определено или у вас нет прав на него.
- `bad-gang` — `gang` не является числом.
- `bad-user` — `user` не является числом.
- `bad-type` — `type` не является числом от 1 до 4.

Состав элемента `data` (такой же объект списка возвращают функции [add](#blacklistadd) и [edit](#blacklistedit), а также поле `dataset.list` функции [show](#blacklistshow)):

| Поле | Описание |
| --- | --- |
| `id` | ID списка. |
| `name` | Название списка. |
| `type` | Вид списка (см. [Виды списков](#blacklisttypes)). |
| `role` | Вид владельца списка: `feed` — список поставщика, обновляется автоматически, `team` — список команды, `user` — персональный список, `admin` — глобальный список, управляемый вручную. |
| `user` | ID пользователя-владельца, 0 если список не персональный. |
| `gang` | ID команды-владельца, 0 если список не командный. |
| `status` | `true`, если список активен. В кампаниях можно выбирать только активные списки. |
| `default` | `true`, если список является списком по умолчанию: его используют кампании, у которых нет явного выбора. |
| `size` | Количество записей в списке. |
| `update` | Unix-время последнего успешного автоматического обновления, 0 если обновлений не было. |
| `locked` | `true`, если записи нельзя менять вручную: список является списком поставщика или зеркалом файла по адресу. |
| `mirror` | `true`, если список является зеркалом файла по адресу `url` (автоматическое обновление включено). |
| `auto` | `true`, если включено автоматическое обновление (для списка поставщика или зеркала). |
| `url` | Адрес зеркалируемого файла, пусто, если список не является зеркалом. |

## Записи списка

**URL вебмастера**: `https://domain.com/api/blacklist/show.json?id={token}&list={list}`

**URL команды**: `https://domain.com/api/blacklist/show.json?id={token}&list={list}&scope=gang`

**URL администратора**: `https://domain.com/api/blacklist/show.json?id={token}&list={list}&scope=admin`

**Метод**: `GET` или `POST`.

Возвращает записи одного списка с постраничной разбивкой, поиском и фильтрами. Функция работает для любого списка текущего пространства, в том числе заблокированного для ручного редактирования (списки поставщиков и зеркала). Записи отсортированы по адресу (для списков заголовков — по значению).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `list`* | Обязательный параметр. ID списка в текущем пространстве. |
| `search` | Поиск по записям; смысл зависит от вида списка (см. ниже). Пустая строка отключает поиск. |
| `comment` | Фильтр по коду причины, только цифры, от 0 до 255 (см. [Коды причин](#blacklistcomments)). `0` или отсутствие: без фильтра. Значение, которое не является числом или больше 255, возвращает `bad-comment`. |
| `type` | Только для списков заголовков: фильтр по идентификатору заголовка, от 0 до 255 (см. [Идентификаторы заголовков](#blacklistheaders)). `0` или отсутствие: без фильтра. Нечисловое значение или значение вне диапазона возвращает `bad-type`. Для остальных видов игнорируется. |

| `show` | Количество записей на странице, от 1 до 1000. По умолчанию 50. |

Смысл `search` в зависимости от вида списка:

- IP-адреса — точный IPv4-адрес. Неверный адрес возвращает `bad-search`.
- IP-подсети — возвращает подсети, содержащие этот IPv4-адрес. Неверный адрес возвращает `bad-search`.
- IPv6-адреса — возвращает подсети, содержащие этот IPv6-адрес. Неверный адрес возвращает `bad-search`.
- Заголовки — подстрока значения записи.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |

| `error` | Код ошибки для статуса `error` (см. ниже) |

Коды ошибок:

- `scope` — пространство не определено или у вас нет прав на него.
- `bad-gang` — `gang` не является числом.
- `bad-user` — `user` не является числом.
- `no-list` — `list` не передан или равен 0.
- `bad-list` — список не найден в текущем пространстве.
- `bad-search` — `search` не является допустимым адресом для видов списков, которые его требуют.
- `bad-comment` — `comment` не является числом от 0 до 255.
- `bad-type` — `type` не является числом от 0 до 255 (списки заголовков).

## Настройка списка

**URL вебмастера**: `https://domain.com/api/blacklist/edit.json?id={token}`

**URL команды**: `https://domain.com/api/blacklist/edit.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/blacklist/edit.json?id={token}&scope=admin`

**Метод**: `POST`.

Изменяет настройки списка. Это частичное обновление: изменяются только параметры, присутствующие в запросе. Если ни одной настройки не передано, список возвращается без изменений. Вид списка изменить нельзя. Функция работает и для заблокированных списков: списки поставщиков и зеркала можно настраивать, заблокированы только их записи. Изменения флагов `status` и `default` применяются к кампаниям сразу.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `list`* | Обязательный параметр. ID списка в текущем пространстве. |
| `name` | Новое название списка (очищается так же, как в [add](#blacklistadd)). Пустое название возвращает `bad-name`. |
| `status` | Флаг активности, `1` или `0`. В кампаниях можно выбирать только активные списки. См. примечание о логических значениях ниже. |
| `default` | Флаг "по умолчанию", `1` или `0`. Список по умолчанию используется кампаниями, у которых нет явного выбора. |
| `key` | Только для списков поставщиков: ключ доступа для получения обновлений. Для остальных списков игнорируется. |
| `auto` | `1` или `0`. Для списка поставщика — переключатель автоматического обновления. Для остальных списков — включает или выключает зеркалирование файла по адресу (см. ниже). |
| `url` | Не для списков поставщиков. Адрес зеркалируемого CSV-файла. Пустая строка очищает адрес. |
| `period` | Не для списков поставщиков. Период обновления зеркала, в секундах (см. ниже). |

> **Внимание!** Логические параметры (`status`, `default`, `auto`) не интерпретируются как слова: `0`, пустая строка и `"0"` выключают флаг, **любое другое значение включает его, в том числе строка `false`**. Всегда передавайте `1` или `0`.

Зеркалирование файла (параметры `url`, `period`, `auto`):

Ручной список может стать автоматической копией CSV-файла, опубликованного по адресу. Файл должен быть в том же формате, который функция [export](#blacklistexport) выдаёт для этого вида списка. При каждом обновлении список становится точной копией файла: записи, которых нет в файле, удаляются, а ручные правки теряются. Пока зеркалирование включено, список заблокирован и его записи нельзя менять вручную; чтобы снова править записи, выключите `auto`. Если передан любой из параметров `url`, `period`, `auto`, недостающие берутся из сохранённых настроек, и проверяются следующие правила:

- Адрес должен быть публичной ссылкой `http` или `https` с именем хоста, длиной до 500 символов, без логина и пароля, с портом 80 или 443 (или без порта). Хост, заданный числом, должен быть публичным IPv4-адресом. Иначе возвращается `bad-url`. Включение `auto` при пустом адресе также возвращает `bad-url`.
- Период должен быть одним из значений, допустимых для списка: 10800, 21600, 43200, 86400, 259200, 604800 секунд (3 часа, 6 часов, 12 часов, 1 день, 3 дня, 1 неделя) для персональных и командных списков, а для глобальных дополнительно 600, 1800, 3600 секунд (10, 30 минут, 1 час). Допустимые значения также возвращаются в поле `periods` списка. Неверный период при включённом `auto` возвращает `bad-period`; при выключенном `auto` период молча сохраняется как 0.
- Список не должен быть выбран в настройках фильтрации как список, в который система автоматически записывает блокируемые адреса, иначе возвращается `target`: зеркало удалило бы записи, сделанные системой.
- У пользователя или команды может быть не более 5 зеркалируемых списков, иначе возвращается `limit`. У глобальных списков такого ограничения нет.
- При изменении адреса или включении `auto` состояние обновления списка сбрасывается, и файл загружается заново при ближайшем фоновом обновлении.
- Файл применяется, только если в нём есть хотя бы одна корректная строка, не более 10% строк некорректны, а (для персональных и командных списков) строк не больше 200 000 (500 для списков заголовков) и размер не превышает 8 388 608 байт (268 435 456 байт для глобальных списков). Файл, не прошедший проверки, не применяется; поля `check` и `fail` списка показывают последнюю попытку и количество неудач подряд.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `message` | Локализованное пояснение для ошибок `bad-url`, `bad-period`, `target` и `limit`. |
| `data` | Объект обновлённого списка (см. [Список чёрных списков](#blacklistlist)). |

Коды ошибок:

- `scope` — пространство не определено или у вас нет прав на него.
- `bad-gang` — `gang` не является числом.
- `bad-user` — `user` не является числом.
- `no-list` — `list` не передан или равен 0.
- `bad-list` — список не найден в текущем пространстве.
- `bad-name` — название пустое.
- `bad-url` — адрес файла неверен, либо `auto` включён при пустом адресе.
- `bad-period` — период обновления не допускается для списка при включённом `auto`.
- `target` — список выбран в настройках фильтрации для автоматической записи блокируемых адресов, поэтому зеркалирование включить нельзя.
- `limit` — достигнут предел в 5 зеркалируемых списков.
- `db` — изменения не удалось сохранить.

**Пример успешного ответа сервера:**

```json
{

    "data": {
        "id": 13,
        "name": "Corporate networks",
        "type": 2,
        "role": "user",
        "user": 123,
        "gang": 0,
        "status": true,
```

## Добавление записи

**URL вебмастера**: `https://domain.com/api/blacklist/block.json?id={token}`

**URL команды**: `https://domain.com/api/blacklist/block.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/blacklist/block.json?id={token}&scope=admin`

**Метод**: `POST`.

Добавляет одну запись в список. Если в списке уже есть запись с тем же идентифицирующим значением, запись обновляется вместо дублирования (upsert); поле `added` ответа сообщает, что произошло. Функция не работает для заблокированных списков (списки поставщиков и зеркала): возвращается `locked`.

Набор обязательных полей зависит от вида списка:

- IP-адреса: `ip`.
- IP-подсети и IPv6-адреса: `ip` и `size`.
- Заголовки: `value` и `type` (дополнительно `regexp` и `white`).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `list`* | Обязательный параметр. ID списка в текущем пространстве. |
| `ip`* | Обязательный параметр для IP-адресов, IP-подсетей и IPv6-адресов. IPv4-адрес для IP-адресов и IP-подсетей, IPv6-адрес для IPv6-адресов. Для подсетей может быть любым адресом подсети: он округляется вниз до первого адреса подсети. Отсутствие значения возвращает `no-ip`. Неверные, частные и зарезервированные адреса (например, `10.0.0.1`, `192.168.1.1`, `127.0.0.1`, `0.0.0.0`) возвращают `bad-ip`. |
| `size`* | Обязательный параметр для IP-подсетей и IPv6-адресов. Длина префикса: от 8 до 31 для IP-подсетей, от 32 до 128 для IPv6-адресов (отдельный IPv6-адрес — 128). Отсутствующее значение или значение вне диапазона возвращает `bad-size`. |
| `value`* | Обязательный параметр для заголовков. Текст заголовка или регулярное выражение, до 250 символов, UTF-8. Отсутствие значения возвращает `no-value`; пустое значение, неверный UTF-8 или текст длиннее 250 символов возвращает `bad-value`. |
| `type`* | Обязательный параметр для заголовков. Идентификатор заголовка, от 1 до 255 (см. [Идентификаторы заголовков](#blacklistheaders)). Отсутствующее значение или значение вне диапазона возвращает `bad-type`. |
| `regexp` | Только для заголовков. `1`: `value` — регулярное выражение с разделителями (например, `/bot\d+/i`); `0`: `value` ищется как подстрока без учёта регистра. По умолчанию 0. Выражение при сохранении не проверяется; неверное выражение пропускается при фильтрации. |
| `white` | Только для заголовков. `1`: белое правило, визит блокируется, если заголовок **не** совпадает или отсутствует; `0`: чёрное правило, визит блокируется, если заголовок совпадает. По умолчанию 0. |
| `comment` | Код причины от 0 до 255 (см. [Коды причин](#blacklistcomments)). По умолчанию 0. Нечисловое значение считается равным 0. |
| `ttl` | Unix-время, когда запись истекает. По умолчанию 0: никогда. Значение больше 4 294 967 295 уменьшается до этого максимума. |

Срок действия записи (`ttl`): запись с заданным `ttl` автоматически удаляется после указанного времени; очистка выполняется каждую минуту и пересчитывает размер списка. До этого момента запись остаётся в силе, поэтому истёкшая запись может продолжать блокировать визиты ещё до минуты. Записи, которые пишет автоматическая блокировка системы, также получают собственный `ttl`.

Идентифицирующее значение записи (что считается "той же" записью):

- IP-адреса: адрес.
- IP-подсети и IPv6-адреса: первый адрес подсети вместе с длиной префикса (перед сравнением адрес округляется до начала подсети).
- Заголовки: пара `type` и `value`; значение сравнивается без учёта регистра, кроме правил с `regexp`, которые сравниваются точно.

Если запись найдена, обновляются только поля, переданные в запросе: `comment` и `ttl` для всех видов, а также `value`, `type`, `regexp` и `white` для заголовков; дубликаты того же правила для заголовка, если они есть, удаляются. Иначе добавляется новая запись. Количество записей в списке не ограничено. Для подсетей см. примечание о задержке во [введении](#blacklistfilter).

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `data` | Объект записи (см. [Записи списка](#blacklistshow)) с дополнительным полем `added`: `true`, если добавлена новая запись, `false`, если обновлена существующая. |

Коды ошибок:

- `scope` — пространство не определено или у вас нет прав на него.
- `bad-gang` — `gang` не является числом.
- `bad-user` — `user` не является числом.
- `no-list` — `list` не передан или равен 0.
- `bad-list` — список не найден в текущем пространстве.
- `locked` — список является списком поставщика или зеркалом и не может быть изменён вручную.
- `no-ip` — `ip` не передан.
- `no-value` — `value` не передан.
- `bad-size` — длина префикса вне допустимого диапазона.
- `bad-type` — идентификатор заголовка не является числом от 1 до 255.
- `bad-ip` — адрес неверен, частный или зарезервированный.
- `bad-value` — значение заголовка пустое, длиннее 250 символов или не в UTF-8.
- `db` — запись не удалось сохранить.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "id": 503,
        "ip": "12.34.56.0",
        "size": 24,
        "to": "12.34.56.255",
        "comment": 3,
        "ttl": 0,
        "added": true
    }
}
```

**Пример успешного ответа сервера для списка заголовков:**

```json
{
    "status": "ok",
    "data": {
        "id": 77,
        "value": "HeadlessChrome",
        "type": 1,
        "regexp": false,
        "white": false,
        "comment": 6,
        "ttl": 0,
        "added": false
    }
}
```

**Пример ответа сервера с ошибкой:**

```json

    "status": "error",
```

## Импорт записей

**URL вебмастера**: `https://domain.com/api/blacklist/import.json?id={token}&list={list}`

**URL команды**: `https://domain.com/api/blacklist/import.json?id={token}&list={list}&scope=gang`

**URL администратора**: `https://domain.com/api/blacklist/import.json?id={token}&list={list}&scope=admin`

**Метод**: `POST` с `Content-Type: multipart/form-data`. CSV-файл передаётся в поле `import`; `list` можно передать в строке запроса или в форме.

Сливает записи CSV-файла со списком. Импорт никогда не удаляет записи: записи, присутствующие в файле, обновляются или добавляются, а все остальные записи списка остаются как есть. Функция не работает для заблокированных списков (списки поставщиков и зеркала). Чтобы полностью заменить содержимое списка, удалите или пересоздайте список либо используйте зеркалирование файла (см. [edit](#blacklistedit)).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `list`* | Обязательный параметр. ID списка в текущем пространстве. |
| `import`* | Обязательный параметр. CSV-файл (см. ниже). |
| `gang` | Только для пространства `admin`: ID команды, выбирает владельца списка. |
| `user` | Только для пространства `admin`: ID пользователя, выбирает владельца списка. |

Формат файла:

- Кодировка UTF-8; BOM в начале пропускается. Строки заголовка нет: строка заголовка была бы засчитана как отклонённая. Пустые строки пропускаются.
- Разделитель определяется автоматически среди запятой, точки с запятой и табуляции. Значения могут быть обрамлены двойными кавычками. Файлы, созданные функцией [export](#blacklistexport), принимаются всегда.
- Столбцы позиционные; отсутствующие замыкающие столбцы считаются равными 0.
- Каждая строка проверяется так же, как в [block](#blacklistblock); некорректная строка засчитывается как отклонённая и пропускается, импорт она не останавливает.

Столбцы файла в зависимости от вида списка (см. [Виды списков](#blacklisttypes)):

| Вид списка | Столбцы |
| --- | --- |
| IP-адреса | `ip`, `comment`, `ttl` |
| IP-подсети | `ip`, `size`, `comment`, `ttl` |
| IPv6-адреса | `ip`, `size`, `comment`, `ttl` |
| Заголовки | `value`, `type`, `regexp`, `comment`, `ttl`, `white` |

Правила слияния:

- Записи сопоставляются по идентифицирующему значению, как в [block](#blacklistblock). Найденная запись **обновляется** значениями `comment` и `ttl` из файла (для заголовков также `value`, `type`, `regexp` и `white`); отсутствующий в файле столбец перезаписывает сохранённое значение нулём, поэтому строка без `ttl` делает запись бессрочной. Остальные строки **добавляются**.
- Записи списка, которых нет в файле, не затрагиваются. Единственное удаление — удаление лишних копий правила для заголовка, присутствующего в файле; они учитываются в `del`.
- Повторяющаяся строка внутри файла засчитывается как обновление.
- Количество строк не ограничено. Размер файла ограничен: 8 388 608 байт (8 МиБ) для персональных и командных списков, 268 435 456 байт (256 МиБ) для глобальных списков, а также лимитом загрузки сервера; файл большего размера возвращает `limit`.
- Файл без единой корректной строки не является ошибкой: `add` равен 0, а `bad` — числу строк.
- Для списков вида IP-подсети см. примечание о задержке во [введении](#blacklistfilter).

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `data` | Результат импорта, состав описан ниже. |

Коды ошибок:

- `scope` — пространство не определено или у вас нет прав на него.
- `bad-gang` — `gang` не является числом.
- `bad-user` — `user` не является числом.
- `no-list` — `list` не передан или равен 0.
- `bad-list` — список не найден в текущем пространстве.
- `locked` — список является списком поставщика или зеркалом и не может быть изменён вручную.
- `limit` — файл больше допустимого размера или лимита загрузки.
- `no-file` — файл не загружен.
- `bad-file` — загруженный файл не удалось прочитать.
- `db` — записи не удалось сохранить.

Состав элемента `data`:

| Поле | Описание |
| --- | --- |
| `add` | Количество добавленных записей. |
| `upd` | Количество обновлённых записей. |
| `bad` | Количество отклонённых строк (некорректных или не сохранённых). |
| `del` | Количество удалённых дубликатов правил для заголовков. Для списков адресов и подсетей всегда 0. |
| `size` | Итоговое количество записей в списке. |

**Пример реализации отправки запроса:**

```bash
curl -F "import=@nets.csv" "https://domain.com/api/blacklist/import.json?id={token}&list=13"
```

Пример файла `nets.csv` для списка вида IP-подсети:

```
12.34.56.0,24,3,0
78.90.0.0,16,2,1893456000
```

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "data": {
        "add": 1,
        "upd": 1,
        "bad": 0,
        "del": 0,
        "size": 151
    }
}
```

**Пример ответа сервера с ошибкой:**

```json
{
    "status": "error",
    "error": "locked"
}
```

<a id="blacklistexport"></a>
## Экспорт записей

**URL вебмастера**: `https://domain.com/api/blacklist/export.json?id={token}&list={list}`

**URL команды**: `https://domain.com/api/blacklist/export.json?id={token}&list={list}&scope=gang`

**URL администратора**: `https://domain.com/api/blacklist/export.json?id={token}&list={list}&scope=admin`

**Метод**: `GET` или `POST`.

Скачивает все записи списка в виде CSV-файла. Расширение `.json` в адресе обязательно для маршрутизации, но игнорируется: ответом всегда является файл, а не JSON. Функция работает для любого списка текущего пространства, в том числе заблокированного. В файле нет строки заголовка, постраничной разбивки и гарантированного порядка строк; формат в точности тот, который читает функция [import](#blacklistimport) и который должен иметь зеркалируемый файл.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `list`* | Обязательный параметр. ID списка в текущем пространстве. |
| `gang` | Только для пространства `admin`: ID команды, выбирает владельца списка. |
| `user` | Только для пространства `admin`: ID пользователя, выбирает владельца списка. |

Ответом является файл с `Content-Type: text/csv` и именем вложения `filter-<kind>-<list_id>.csv`, где вид (`<kind>`) — `ip`, `net`, `ip6` или `bl`. Строки в зависимости от вида списка, значения разделены запятыми:

| Вид списка | Строка |
| --- | --- |
| IP-адреса | `ip`, `comment`, `ttl` |
| IP-подсети | `ip`, `size`, `comment`, `ttl` |
| IPv6-адреса | `ip`, `size`, `comment`, `ttl` |
| Заголовки | `value` (всегда в двойных кавычках, кавычка внутри удваивается), `type`, `regexp` (0 или 1), `comment`, `ttl`, `white` (0 или 1) |

Коды ошибок (возвращаются в виде JSON до начала вывода файла):

- `scope` — пространство не определено или у вас нет прав на него.
- `bad-gang` — `gang` не является числом.
- `bad-user` — `user` не является числом.
- `no-list` — `list` не передан или равен 0.
- `bad-list` — список не найден в текущем пространстве.

**Пример успешного ответа сервера** (файл `filter-net-13.csv`):

```
12.34.56.0,24,3,0
78.90.0.0,16,2,1893456000
```

**Пример успешного ответа сервера для списка заголовков** (файл `filter-bl-14.csv`):

```
"HeadlessChrome",1,0,6,0,0
"/^python-requests\/\d+/i",1,1,9,0,0
```

**Пример ответа сервера с ошибкой:**

```json
{
    "status": "error",
    "error": "bad-list"
}
```

<a id="blacklisterrors"></a>
## Ошибки

Все функции возвращают ошибки в поле `error` ответа. Коды этого раздела:

| Код | Описание |
| --- | --- |
| `scope` | Все функции. Пространство не определено: пользователь неактивен или заблокирован, не является администратором, но запрашивает `admin`, не является лидером команды, но запрашивает `gang`, либо `user` не является участником команды. |
| `bad-gang` | Все функции, пространство `admin`. `gang` не является числом; в [avail](#blacklistavail) и [add](#blacklistadd) также если команда не существует. |
| `bad-user` | Все функции, пространство `admin`. `user` не является числом; в [avail](#blacklistavail) и [add](#blacklistadd) также если пользователь не существует. |
| `no-site` | [avail](#blacklistavail). Кампания `uid` не найдена в текущем пространстве. |
| `no-user` | [avail](#blacklistavail). `uid` не передан и владелец списков не определён. |
| `no-name` | [add](#blacklistadd). Название списка пустое. |
| `bad-name` | [edit](#blacklistedit). Название списка пустое. |
| `bad-type` | [list](#blacklistlist) и [add](#blacklistadd): вид списка не от 1 до 4. [show](#blacklistshow), [block](#blacklistblock) и [change](#blacklistchange): неверный идентификатор заголовка. |
| `no-list` | Все функции с параметром `list`. `list` не передан или равен 0. |
| `bad-list` | Все функции с параметром `list`. Список не найден в текущем пространстве. |
| `locked` | [block](#blacklistblock), [remove](#blacklistremove), [change](#blacklistchange), [import](#blacklistimport). Список является списком поставщика или зеркалом. |
| `bad-search` | [show](#blacklistshow). Текст поиска не является допустимым адресом для списков адресов и подсетей. |
| `bad-comment` | [show](#blacklistshow). `comment` не является числом от 0 до 255. |
| `no-ip` | [block](#blacklistblock). `ip` не передан. |
| `no-value` | [block](#blacklistblock). `value` не передан. |
| `bad-ip` | [block](#blacklistblock), [change](#blacklistchange). Адрес неверен, частный или зарезервированный. |
| `bad-value` | [block](#blacklistblock), [change](#blacklistchange). Значение заголовка пустое, длиннее 250 символов или не в UTF-8. |
| `bad-size` | [block](#blacklistblock), [change](#blacklistchange). Длина префикса вне допустимого диапазона. |
| `no-item` | [remove](#blacklistremove), [change](#blacklistchange). `item` не передан. |
| `bad-item` | [remove](#blacklistremove), [change](#blacklistchange). Такой записи в списке нет. |
| `duplicate` | [change](#blacklistchange). Запись дублировала бы другую запись списка. |
| `bad-url` | [edit](#blacklistedit). Адрес файла неверен. Сопровождается `message`. |
| `bad-period` | [edit](#blacklistedit). Период обновления не допускается. Сопровождается `message`. |
| `target` | [edit](#blacklistedit). Список используется для автоматической записи блокируемых адресов. Сопровождается `message`. |
| `limit` | [edit](#blacklistedit): более 5 зеркалируемых списков. [import](#blacklistimport): файл слишком велик. |
| `no-file` | [import](#blacklistimport). Файл не загружен. |
| `bad-file` | [import](#blacklistimport). Загруженный файл не удалось прочитать. |
| `db` | [add](#blacklistadd), [edit](#blacklistedit), [del](#blacklistdel), [block](#blacklistblock), [remove](#blacklistremove), [change](#blacklistchange), [import](#blacklistimport). Данные не удалось сохранить. |

<a id="blacklistlimits"></a>
## Ограничения

| Ограничение | Значение |
| --- | --- |
| Название списка | До 100 символов. |
| Количество списков | Не ограничено. |
| Количество записей в списке | Не ограничено. |
| Записей на странице | [show](#blacklistshow): 1–1000, по умолчанию 50. [list](#blacklistlist): 0–1000, 0 означает все списки. |
| Длина префикса | IP-подсети: 8–31. IPv6-адреса: 32–128. |
| Правило для заголовка | Текст до 250 символов, идентификатор заголовка 1–255. |
| Код причины (`comment`) | 0–255. |
| Срок действия (`ttl`) | Unix-время, от 0 (бессрочно) до 4 294 967 295. |
| Размер файла импорта | 8 388 608 байт (8 МиБ) для персональных и командных списков; 268 435 456 байт (256 МиБ) для глобальных списков. Количество строк не ограничено. |
| Зеркалируемые списки | 5 на пользователя или команду; для глобальных списков не ограничено. |
| Зеркалируемый файл | Ссылка до 500 символов, порт 80 или 443. Тот же предел размера, что и для импорта; до 200 000 строк (500 для списков заголовков) для персональных и командных списков, для глобальных не ограничено. |
| Период обновления зеркала | От 3 часов до 1 недели для персональных и командных списков; от 10 минут до 1 недели для глобальных списков. |
| Кэш подсетей | Поиск по IPv4-подсетям кэшируется на 666 секунд (см. [введение](#blacklistfilter)). |
