# Click API — обработка переходов

Click API — это низкоуровневый интерфейс трекера для регистрации переходов и выдачи инструкций клиентскому скрипту. Именно он обеспечивает обработку ссылок потоков: клиентский скрипт (`server.php`), установленный на сайте или хранилище, собирает данные посетителя и отправляет их на один из двух эндпойнтов. Трекер анализирует переход, применяет фильтры и логику TDS, записывает клик в базу и возвращает JSON с инструкцией — что показать и каким методом.

Этот API не использует стандартный токен пользователя. Запросы к нему формируются клиентским скриптом автоматически. Документация предназначена для разработчиков, которые пишут собственные клиентские реализации или интегрируют трекер нестандартным способом.

<a id="tds"></a>
## Регистрация клика по коду потока

**URL**: `https://domain.com/track-tds/{flow}`

Принимает переход по символьному идентификатору потока `{flow}`. Клиентский скрипт отправляет POST-запрос, содержащий данные посетителя. Трекер определяет подходящий путь, фиксирует клик и возвращает инструкцию для показа контента.

Если в строке запроса присутствует параметр `next`, запрос обрабатывается как **второй шаг** (переход с прелендинга на лендинг) — подробнее см. ниже.

Функция принимает на вход POST-тело, состоящее из двух частей:

- содержимое `$_SERVER` на стороне клиента (серверные служебные поля предварительно удаляются);
- поле `cookie` — ассоциативный массив `$_COOKIE` посетителя.

Ключевые поля, которые использует трекер:

| Поле | Описание |
| --- | --- |
| `cookie` | Массив кукиз посетителя. |
| `QUERY_STRING` | Строка GET-параметров запроса; из неё извлекаются метки, идентификаторы и управляющие параметры (см. ниже). |
| `HTTP_USER_AGENT` | User-Agent посетителя для определения браузера, ОС и типа устройства. |
| `HTTP_HOST` | Домен, на котором был зафиксирован переход. |
| `HTTP_REFERER` | Реферер; используется для проверки на ботов. |
| `REMOTE_ADDR` | IP-адрес посетителя (также проверяются `HTTP_CF_CONNECTING_IP`, `HTTP_X_REAL_IP`, `HTTP_X_CLIENT_IP`). |

Параметры из QUERY_STRING (`{flow}?param=value`):

| Параметр | Описание |
| --- | --- |
| `next` | Закодированный ID клика. Если передан, запрос обрабатывается как второй шаг (см. ниже). |
| `utm_source` | Метка UTM Source. |
| `utm_campaign` | Метка UTM Campaign. |
| `utm_content` | Метка UTM Content. |
| `utm_term` | Метка UTM Term. |
| `utm_medium` | Метка UTM Medium. |
| `subid` | Метка Sub ID. |
| `customer` | Метка Customer (также принимается как `utm_user`). |
| `data1`..`data5` | Поля произвольных данных (также принимаются как `d1`..`d5`). |
| `fbclid`, `gclid`, `adclid`, `clid`, `adid` | Идентификатор клика рекламной кампании. Сохраняется в поле `adid`. |
| `cpc` | Цена клика. |
| `cur` | Валюта цены клика. По умолчанию — `usd`. |

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже). |
| `uid` | Символьный идентификатор потока. |
| `way` | Числовой идентификатор выбранного пути. При включённом роторе — строка с историей показанных путей через запятую. |
| `method` | Метод показа контента (см. ниже). |
| `url` | URL для редиректа или загрузки контента. |
| `nocookie` | Если `true` — клиент не устанавливает куки (например, при trafficback). |
| `params` | Объект с макросами для подстановки в URL и контент (см. ниже). |

Коды ошибок:

- `no-id` — не передан символьный идентификатор потока.
- `bad-id` — идентификатор потока не декодируется в числовой ID.
- `bad-flow` — поток с таким ID не найден в базе данных.
- `no-ways` — у потока нет активных путей.
- `no-data` — POST-тело пустое или не передано.
- `db` — ошибка записи клика в базу данных.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "uid": "ef1c",
    "way": 42,
    "method": "http302",
    "url": "https://offer.example.com/?click={click}",
    "nocookie": false,
    "params": {
        "click": "ca1337",
        "flow": "ef1c",
        "geo": "RU",
        "utm_source": "facebook",
        "utm_campaign": "summer24"
    }
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "bad-flow"
}
```

## Регистрация клика по домену

**URL**: `https://domain.com/track-dom/{domain}`

Работает аналогично `track-tds`, но вместо кода потока принимает hostname домена `{domain}`. Трекер ищет поток, привязанный к этому домену, и передаёт управление той же логике TDS.

Используется клиентским скриптом, установленным на паркованном домене, когда нет возможности или нет необходимости передавать код потока явно — поток определяется автоматически по домену запроса.

Формат входных данных, параметры QUERY_STRING, выходные поля, коды ошибок и поведение второго шага полностью совпадают с `track-tds` (см. выше). Дополнительные коды ошибок, специфичные для этого эндпойнта:

- `no-domain` — не передан hostname домена.
- `bad-path` — путь в `REQUEST_URI` некорректен.

## Второй шаг (переход с прелендинга на лендинг)

Если в QUERY_STRING первого запроса (`track-tds` или `track-dom`) присутствует параметр `next` с закодированным ID клика, трекер обрабатывает запрос как второй шаг схемы «прелендинг → лендинг»:

1. Декодирует `next` в числовой ID клика.
2. Находит клик в базе данных и проверяет его принадлежность потоку.
3. Берёт из пути настройки второго шага: URL, сайт и метод работы.
4. Обновляет клик: проставляет признак перехода на второй шаг.
5. Возвращает ответ с методом и URL второго шага.

Для использования второго шага на прелендинге вставьте ссылку через макрос `{next}` (полная ссылка с доменом и потоком) или `{local}` (только строка параметров). Подробнее о настройке путей — в разделе [Потоки и трафик](flows.md).

## Методы показа (поле `method`)

Поле `method` в ответе сервера указывает клиентскому скрипту, как именно показать содержимое по адресу `url`. Подробное описание каждого метода — в разделе [Методы работы с трафиком](method.md).

| Значение | Название | Описание |
| --- | --- | --- |
| `http302` | 302 редирект | Стандартный временный редирект через заголовок `302 Found`. |
| `http301` | 301 редирект | Постоянный редирект через заголовок `301 Moved Permanently`, кешируется браузером. |
| `redirect` | Meta-редирект | HTML-страница «Идёт проверка вашего браузера» с перенаправлением через секунду. |
| `jsgo` | JS-редирект | Пустая страница с `location.replace()`, перенаправление через 500 мс. |
| `iframe` | IFrame | Полноэкранный iframe с целевым сайтом. |
| `proxy` | Curl с rebase | Контент загружается через cURL, в HTML добавляется тег `<base>` для перебазирования путей. |
| `curl` | Curl без rebase | Контент загружается через cURL без изменения путей; все пути к ресурсам должны быть абсолютными. |
| `local` | Локальный файл | Относительный путь к локальному PHP/HTML-файлу; автозамена макросов в содержимом. |
| `site` | Сайт из хранилища | Файл из локального хранилища сайтов (`index.html` / `index.php`) с rebase. |
| `error` | Страница ошибки | HTTP-ответ с кодом из `url`; если `url` пустой — код выбирается случайно по IP. |
| `blank` | Пустая страница | Пустой ответ `200 OK` без содержимого. |
| `raw` | Сырые данные | Тело из поля `data`, Content-Type из поля `type`. |

## Макросы (поле `params`)

Поле `params` в ответе сервера содержит объект с именованными значениями, которые клиентский скрипт подставляет вместо соответствующих макросов в `url` и в содержимое загружаемого сайта. Полный список макросов — в разделе [Потоки и трафик](flows.md#macros).

| Макрос | Значение |
| --- | --- |
| `{click}` | Символьный идентификатор клика. |
| `{flow}` | Символьный идентификатор потока. |
| `{user}` | Идентификатор пользователя трекера. |
| `{geo}` | ISO-код страны клика. |
| `{host}` | Домен, с которого был зафиксирован переход. |
| `{query}` | Строка GET-параметров запроса. |
| `{next}` | Полная ссылка второго шага (с доменом и кодом потока). |
| `{local}` | Относительная ссылка второго шага (только строка параметров). |
| `{direct}` | Прямая ссылка второго шага без редиректа через трекер. |
| `{adid}` | Идентификатор клика рекламной кампании (`fbclid`, `gclid`, `adclid`, `clid`, `adid`). |
| `{data1}`..`{data5}` | Поля произвольных данных. |
| `{subid}` | Метка SubID. |
| `{customer}` | Метка Customer. |
| `{utm_source}` | Метка UTM Source. |
| `{utm_campaign}` | Метка UTM Campaign. |
| `{utm_content}` | Метка UTM Content. |
| `{utm_term}` | Метка UTM Term. |
| `{utm_medium}` | Метка UTM Medium. |
| `{esub}` | Зашифрованная метка SubID. |
| `{eutms}` | Зашифрованная метка UTM Source. |
| `{eutmc}` | Зашифрованная метка UTM Campaign. |
| `{eutmn}` | Зашифрованная метка UTM Content. |
| `{eutmt}` | Зашифрованная метка UTM Term. |
| `{eutmm}` | Зашифрованная метка UTM Medium. |
| `{eutmu}` | Зашифрованная метка Customer. |
| `{ed1}`..`{ed5}` | Зашифрованные поля произвольных данных. |
| `{hide1}`..`{hide6}` | Поля скрытых данных потока или пути. |

## Куки

После успешного ответа клиентский скрипт устанавливает две куки на домен посетителя (если в ответе `nocookie` не равно `true`):

| Имя куки | Значение | Срок хранения |
| --- | --- | --- |
| `{uid}` | ID выбранного пути (`way`) | 86 400 сек (1 день) |
| `x{uid}` | Закодированный ID клика | 2 592 000 сек (30 дней) |

Здесь `{uid}` — символьный код потока. Обе куки устанавливаются с атрибутами `SameSite=None; Secure` и привязаны к домену из заголовка `HTTP_HOST`.

Кука `x{uid}` используется пиксельными эндпойнтами для сопоставления просмотра или конверсии с конкретным кликом.
