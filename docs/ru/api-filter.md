# Фильтрация

Функции фильтрации позволяют вам максимально быстро проверять визиты на ваши сайты. Они вынесены в отдельный интерфейс, который имеет минимальное время ответа и максимальную производительность.

В этом же разделе находятся функции управления кампаниями фильтрации, журнала визитов и статистики проверенных визитов, а также добавления записей в чёрные списки. Сами чёрные списки (создание списков, редактирование, импорт и экспорт записей) управляются отдельным [API чёрных списков](api-blacklist.md).

<a id="check"></a>
## Проверка визита

URL: `https://domain.com/fltr/{user}-{key}-{id}`

В адресе функции вместо `{user}` и `{key}` укажите API ID и ключ из [профиля](/profile), вместо `{id}` указывается идентификатор добавленного вами фильтр-сайта. Конкретный URL вы можете получить, нажав на кнопку "Инструкция" соответствующего сайта в [вашем личном кабинете](/filter).

Чтобы проверить свой визит, вам необходимо отправить POST-запрос на указанный выше URL. В качестве тела запроса передайте поля своего массива `$_SERVER` - мы проанализируем их и покажем ответ в формате JSON. Успешный ответ включает в себя поля `status`, `action` и `url`. Поле `status` всегда содержит значение `ok`. Поле `action` ответа будет содержать `allow` или `deny` в зависимости от результатов проверки, поле `url` будет содержать соответствующий URL-адрес. В ошибочном ответе поле `status` будет содержать `error`, код ошибки будет указан в поле `error`. Ответ всегда имеет HTTP-статус 200 и формат JSON; у URL нет расширения формата. Решение дублируется в заголовке ответа `X-Action`: `allow` или `deny` (в ошибочном ответе всегда `deny`).

POST-часть запроса должна быть в формате `x-www-form-urlencoded`, формат JSON не поддерживается: запрос с пустым телом (в том числе с телом JSON) возвращает ошибку `no-data`. Мы анализируем следующие поля из массива `$_SERVER`:

HTTP_USER_AGENT, HTTP_ACCEPT, HTTP_ACCEPT_CHARSET, HTTP_ACCEPT_ENCODING, HTTP_ACCEPT_LANGUAGE, HTTP_AUTHORIZATION, HTTP_CACHE_CONTROL, HTTP_CONNECTION, HTTP_CONTENT_DISPOSITION, HTTP_DATE, HTTP_EXPECT, HTTP_FROM, HTTP_HOST, HTTP_IF_MATCH, HTTP_IF_MODIFIED_SINCE, HTTP_IF_NONE_MATCH, HTTP_IF_RANGE, HTTP_IF_UNMODIFIED_SINCE, HTTP_MAX_FORWARDS, HTTP_PRAGMA, HTTP_PROXY_AUTHORIZATION, HTTP_RANGE, HTTP_REFERER, HTTP_TE, HTTP_TRAILER, HTTP_TRANSFER_ENCODING, HTTP_UPGRADE, HTTP_VIA, HTTP_X_FORWARDED_FOR, REMOTE_ADDR, REMOTE_PORT, REQUEST_METHOD, REQUEST_URI, QUERY_STRING, HTTP_CF_CONNECTING_IP, HTTP_CLIENT_IP, HTTP_X_REAL_IP, HTTP_X_PURPOSE, HTTP_X_FB_HTTP_ENGINE, HTTP_CF_CONNECTING_IPV6, HTTP_X_FRAME_OPTIONS, HTTP_X_WAP_PROFILE, HTTP_PRIORITY, HTTP_SEC_FETCH_MODE, HTTP_SEC_FETCH_SITE, HTTP_SEC_FETCH_DEST, HTTP_SEC_FETCH_USER, HTTP_SEC_CH_UA, HTTP_SEC_CH_UA_MOBILE, HTTP_SEC_CH_UA_PLATFORM, HTTP_DNT, HTTP_ORIGIN, HTTP_UPGRADE_INSECURE_REQUESTS, HTTP_SAVE_DATA, HTTP_X_FORWARDED_HOST, HTTP_X_FORWARDED_PROTO, REQUEST_SCHEME

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки |
| `action` | Требуемое **действие** по результатам проверки: `allow` для легитимного визита (показать целевой сайт) или `deny` для визита подозрительного (показать сайт-заглушку) |
| `result` | Реальный **результат проверки** трафика, который не зависит от включенного режима обучения: `allow` для легитимного визита (показать целевой сайт) или `deny` для визита подозрительного (показать сайт-заглушку). В режиме обучения значение `result` может отличаться от значения `action`. |
| `url` | URL сайта для запроса, зависит от результатов проверки. |
| `target` | URL целевого сайта, при наличии показывается всегда независимо от результатов проверки. |
| `dummy` | URL сайта-заглушки, при наличии показывается всегда независимо от результатов проверки. |
| `type` | Тип показываемого сайта: `black` для целевого сайта, `white` для сайта-заглушки. Всегда соответствует `action` (`allow` — `black`, `deny` — `white`); по этому полю ориентируется файл, который создаёт функция [Скачать файл фильтрации](#filtermake). |
| `ip` | IP-адрес посетителя, определённый по заголовкам запроса (`false`, если определить его не удалось). |
| `geo` | Двухбуквенный код страны посетителя в нижнем регистре (`zz`, если страна не определена). |
| `reason` | Код результата проверки (см. [коды результата проверки](#filterreasons) ниже): `0`, если визит прошёл все проверки. В режиме обучения это реальный результат проверки, как и в `result`. Для кампаний на паузе и выключенных кампаний равен `0`. |
| `error` | Идентификатор ошибки: `access-denied` при отсутствии доступа к системе проверки (пользователь заблокирован, неверный ключ или кампания принадлежит другому пользователю), `bad-request` в случае ошибочного указания адреса URL проверки, `bad-site` если указанный сайт не найден, `no-data` если тело запроса пустое. |

В полях `url`, `target` и `dummy` макросы `{geo}` (код страны в нижнем регистре), `{geoup}` (код страны в верхнем регистре) и `{ip}` (IP-адрес посетителя) заменяются на их значения.

**Пример реализации отправки запроса:**

```php
$curl = curl_init( 'https://domain.com/fltr/123-abcd-45' );
curl_setopt( $curl, CURLOPT_POST, true );
curl_setopt( $curl, CURLOPT_POSTFIELDS, $_SERVER );
curl_setopt( $curl, CURLOPT_RETURNTRANSFER, true );
$result = curl_exec( $curl );
curl_close( $curl );
$result = $result ? json_decode( $result, true ) : [];
if ( isset( $result['action'] ) && $result['action'] == 'allow' ) {
    include( 'target-index.php' );
} else include( 'dummy-index.php' );
```

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "result": "allow",
    "action": "allow",
    "type": "black",
    "url": "http://black.site/url",
    "ip": "91.203.45.12",
    "geo": "ru",
    "reason": 0,
    "target": "http://black.site/url",
    "dummy": "http://white.site/"
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "access-denied"
}
```

<a id="filterreasons"></a>
### Коды результата проверки и порядок проверок

Поле `reason` ответа и поле `result` [журнала визитов](#filterlog) содержат один из следующих кодов:

- `0` - визит прошёл все проверки (показан целевой сайт) или IP-адрес посетителя входит в белый список `wl`.
- `1` - запрос к некорректному пути: служебные файлы, такие как favicon, карты исходного кода, манифесты, `ads.txt`.
- `2` - трафик с неподходящего устройства: тип устройства (`mobile`), операционная система (`os`) или браузер (`browser`) не разрешены.
- `3` - запрос из заблокированной страны (страны нет в `geo` или она есть в `nogeo`).
- `4` - IP-адрес в чёрном списке.
- `5` - IP-подсеть в чёрном списке.
- `6` - IPv6-адрес в чёрном списке.
- `7` - один из заголовков запроса в чёрном списке, заголовок, требуемый белым правилом, отсутствует или не соответствует ему, либо пустой User-Agent.
- `8` - бот или предпросмотр сайта: запросы предпросмотра браузеров и мессенджеров, прокси-переводчики, рефереры шпионских сервисов, отсутствие IP-адреса, бот или нераспознанный User-Agent.
- `9` - трафик по неподходящему протоколу (`proto`).
- `10` - неподходящий язык посетителя (`langs`, `nolangs`, `lang`).
- `11` - первые мусорные визиты (счётчик `trash`, он уменьшается на единицу с каждым таким визитом) или запрос к пути, который обычно запрашивают сканеры (файлы конфигурации, `robots.txt`, `/.env` и так далее).
- `12` - URL в чёрном списке (нет совпадения с `uwl` или есть совпадение с `ubl`).
- `13` - нет идентификатора клика рекламной сети (`adid`).
- `14` - визит вне расписания кампании (`wd1`..`wd7`, `fh`, `fm`, `th`, `tm`, `tz`).

Проверки выполняются в следующем порядке, первая сработавшая определяет результат: белый список IP `wl` (`0`) → предпросмотры, переводчики и отсутствие IP (`8`) → некорректные и сканирующие пути (`1`, `11`) → User-Agent (`7`, `8`) → устройство, операционная система и браузер (`2`) → протокол (`9`) → страна и язык (`3`, `10`) → идентификатор клика (`13`) → списки URL (`12`) → чёрные списки IP-адресов и подсетей (`4`, `5`, `6`) → правила заголовков (`7`) → первые мусорные визиты (`11`) → расписание (`14`).

Правила заголовков в чёрных списках бывают двух видов: чёрное правило блокирует визит, если заголовок совпадает со значением, белое правило блокирует визит, если заголовок отсутствует или не совпадает со значением (см. [Заблокировать IP-адрес или заголовок](#filterblock)).

Режимы работы кампании (`mode`):

- В режиме паузы (`1`) ответ всегда `deny`, в выключенном режиме (`2`) всегда `allow`; проверки не выполняются.
- В режимах обучения (`3`, `4`) выполняются все проверки, но `action`, `type` и `url` принудительно соответствуют сайту-заглушке (`3`) или целевому сайту (`4`); `result` и `reason` содержат реальный результат проверки.

Каждый проверенный визит записывается в журнал визитов кампании (см. [Журнал визитов](#filterlog)), если только он не исключён режимом журнала кампании (`log`, см. [Настройка кампании](#filterset)). Визиты кампаний на паузе и выключенных кампаний в журнал не записываются. Счётчики кампании (`stats` в [Списке кампаний](#filterlist)) увеличиваются для каждого визита по реальному результату проверки: `black` для разрешённых визитов, `white` для заблокированных (на паузе каждый визит считается заблокированным, в выключенном режиме - разрешённым).

## Пространства и владельцы кампаний

Функции управления кампаниями и просмотра журнала визитов работают в одном из трёх пространств, выбираемых параметром `scope` (см. [API-интерфейс](api.md)). Это функции [Настройка кампании](#filterset), [Список кампаний](#filterlist), [Получение данных кампании](#filterget), [Удаление кампании](#filterdel), [Скачать файл фильтрации](#filtermake), [Заблокировать IP-адрес или заголовок](#filterblock), [Журнал визитов](#filterlog) и [Статистика визитов](#filterstats). Пространство определяет, чьи кампании функция может видеть и изменять. Параметр `scope` читается только из строки запроса, даже если сам запрос отправляется методом POST. Проверка визита и [постбек](#filterpostback) пространства не используют.

| Пространство | Описание |
| --- | --- |
| `scope=user` | По умолчанию. Ваши собственные кампании. Доступно всем активным пользователям. |
| `scope=gang` | Псевдоним: `team`. Кампании всех участников вашей команды. Доступно только лидерам команды. Необязательный параметр `user` ограничивает функцию одним участником вашей команды; если пользователь не входит в вашу команду, возвращается ошибка `scope`. |
| `scope=admin` | Псевдонимы: `sys`, `system`, `all`. Только для администраторов. Без `gang` и `user` функция работает с кампаниями всех пользователей. Параметр `user` ограничивает её кампаниями одного пользователя, `gang` - кампаниями участников одной команды; если переданы оба параметра, кампания должна удовлетворять обоим условиям. |

Дополнительные параметры выбора пространства (читаются из строки запроса или из тела POST):

| Поле | Описание |
| --- | --- |
| `gang` | Только для пространства `admin`: ID команды. |
| `user` | Пространство `gang`: ID участника команды. Пространство `admin`: ID пользователя. В обоих пространствах параметр обязателен при создании новой кампании функцией [Настройка кампании](#filterset): кампания создаётся для этого пользователя. |
| `uu` | Только для ключей администраторов: ID пользователя, от имени которого выполняется запрос. Например, `scope=user&uu=123` работает с кампаниями пользователя 123. |

Примечания:

- Если пространство не определено (вы не лидер команды, у вас нет прав администратора, `user` не входит в вашу команду, аккаунт заблокирован или неактивен), возвращается ошибка `scope`.
- Кампания вне текущего пространства считается несуществующей: например, возвращается `no-site`.
- Ссылки `api` (а также ссылки постбеков из [Получения данных кампании](#filterget) и файл функции [Скачать файл фильтрации](#filtermake)) всегда содержат API-ключ **владельца** кампании, а не ключ вызывающего. В пространствах команды и администратора они раскрывают ключи других пользователей, поэтому храните такие ответы и файлы в тайне.
- Чёрные списки, которые подключаются к кампаниям и получают новые записи, управляются отдельным [API чёрных списков](api-blacklist.md).

<a id="filterset"></a>
## Настройка кампании

**URL вебмастера**: `https://domain.com/api/filter/set.json?id={token}&domain={host}`

**URL команды**: `https://domain.com/api/filter/set.json?id={token}&domain={host}&scope=gang&user={user}`

**URL администратора**: `https://domain.com/api/filter/set.json?id={token}&domain={host}&scope=admin&user={user}`

Функция изменяет параметры кампании фильтрации или создаёт новую кампанию. Если передан идентификатор кампании в поле `uid`, функция будет изменять существующую кампанию по этому идентификатору. Если идентификатор не передан, но передан домен кампании в поле `domain`, функция попытается найти кампанию с указанным доменом, а если её нет - создаст новую. Новая кампания настраивается остальными переданными параметрами в том же вызове. Параметры, которые не переданы, сохраняют свои значения. Если переданы и `uid`, и `domain`, а `domain` отличается от сохранённого названия, кампания переименовывается.

Функция работает в [пространстве](#filterscopes) запроса. В пространствах команды и администратора для создания кампании обязателен параметр `user` (владелец новой кампании).

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `uid` | Идентификатор кампании фильтрации (рекомендуется). |
| `domain` | Домен или название кампании фильтрации (используйте уникальные имена). Название используется только для поиска кампании: домен визита с ним не сравнивается. |
| `mode` | Режим работы кампании (см. ниже) |
| `geo` | Список двухбуквенных ISO-кодов стран, в которых работает фильтр. Указывается массивом или строкой через запятую, например: `ru,kz,by`. Если список содержит `ww` или `zz`, весь список сохраняется пустым. |
| `mblack` | Режим работы целевого сайта (см. ниже) |
| `mwhite` | Режим работы сайта-заглушки (см. ниже) |
| `black` | Целевой сайт: ссылка или название файла. |
| `white` | Сайт-заглушка: ссылка или название файла. |
| `trash` | Количество мусорных визитов, целое число, по умолчанию - 0. |
| `proto` | Версия IP-протокола (см. ниже) |
| `mobile` | Вид допустимого трафика (см. ниже) |
| `os` | Допустимые операционные системы (см. ниже), массив или список ID через запятую |
| `browser` | Допустимые браузеры (см. ниже), массив или список ID через запятую |
| `ipmain` | Проверять только основной IP-адрес запроса на попадание в чёрный список, 0 или 1 (по умолчанию). |
| `lang` | Проверять язык посетителя на попадание в список разрешенных стран, 0 или 1 (по умолчанию). |
| `adid` | Проверять идентификатор клика рекламной сети, 0 (по умолчанию) или 1. |
| `list` | Список ID фильтров трафика (чёрных списков), массив или список через запятую, по умолчанию пустой. Принимаются только списки, доступные владельцу кампании (системные, персональные и списки команды, см. [API чёрных списков](api-blacklist.md)); остальные ID молча отбрасываются. Если список пуст, кампания использует все активные списки по умолчанию. |
| `langs` | Список двухбуквенных ISO-кодов допустимых языков, массив или список через запятую, по умолчанию пустой. |
| `nogeo` | Список двухбуквенных ISO-кодов стран, доступ из которых запрещён. Указывайте в случае пустого списка разрешенных стран. Если список содержит `ww` или `zz`, весь список сохраняется пустым. |
| `uwl` | Белый список слов в URL, указывается текстом по одному в строке. Слова, разделённые запятыми внутри одной строки, должны присутствовать в URL все. |
| `ubl` | Чёрный список слов в URL, указывается текстом по одному в строке, в том же формате, что и `uwl`. |
| `wl` | Белый список IP-адресов, указывается текстом по одному в строке, может содержать IP-адреса и подсети. |
| `log` | Режим журнала визитов (см. ниже). |
| `wd1`..`wd7` | Дни недели, в которые визиты разрешены, 0 или 1: `wd1` - понедельник, `wd7` - воскресенье. Визиты в остальные дни блокируются (причина `14`). |
| `fh`, `fm` | Начало ежедневного временного окна: час (0-23) и минута (0-59). |
| `th`, `tm` | Конец ежедневного временного окна: час (0-23) и минута (0-59). Если начало позже конца, окно переходит через полночь. |
| `tz` | Часовой пояс расписания в формате IANA, например `Europe/Berlin`. Неизвестный идентификатор сохраняется как пустое значение (используется часовой пояс сервера). |
| `user`, `gang` | Параметры выбора пространства, см. [Пространства](#filterscopes). В пространствах команды и администратора для создания кампании обязателен `user`. |

Режимы работы кампании (`mode`):

- `0` - Автоматика: фильтр включен (по умолчанию)
- `1` - Пауза: всегда показывать сайт-заглушку
- `2` - Выключен: всегда показывать целевой сайт
- `3` - Обучение: всегда показывать сайт-заглушку
- `4` - Обучение: всегда показывать целевой сайт

Режимы работы целевого сайта (`mblack`) и сайта-заглушки (`mwhite`):

- `0` - Перенаправить по ссылке (302)
- `5` - Перенаправить и склеить домен (301)
- `6` - Перенаправить через отдельную страницу (meta)
- `9` - Перенаправить скриптом (JS)
- `1` - Открыть файл с таким названием
- `2` - Показать эту ссылку во фрейме
- `7` - Показать контент по ссылке (curl)
- `3` - Показать контент по ссылке без изменений
- `4` - Встроить в WordPress
- `8` - Показать пустую страницу

Версии IP-протокола (`proto`):

- `0` - Принимать трафик любого протокола (по умолчанию)
- `1` - Принимать только трафик IPv4
- `2` - Принимать только трафик IPv6

Виды допустимого трафика (`mobile`):

- `0` - Любой трафик (по умолчанию)
- `1` - Только мобильный трафик
- `2` - Только десктоп-трафик
- `3` - Мобильный трафик: только iOS
- `4` - Мобильный трафик: кроме iOS

Допустимые операционные системы (`os`):

- `5` - Android
- `8` - BlackBerry
- `3` - Linux
- `2` - MacOS
- `7` - Symbian
- `1` - Windows
- `6` - Windows Mobile
- `4` - iOS

Допустимые браузеры (`browser`):

- `1` - Chrome
- `6` - Edge
- `7` - Facebook
- `2` - Firefox
- `8` - Instagram
- `3` - MSIE
- `5` - Opera
- `4` - Safari (определяется только на iOS и macOS)
- `9` - Tik-Tok
- `10` - WebView (определяется только на iOS и macOS)

Режимы журнала визитов (`log`):

- `0` - Записывать все визиты
- `1` - Записывать только целевые визиты (разрешённые)
- `2` - Записывать только визиты на заглушку (заблокированные)
- `3` - Не записывать визиты

Расписание кампании (`wd1`..`wd7`, `fh`, `fm`, `th`, `tm`, `tz`): визит разрешён только в выбранные дни недели и внутри ежедневного временного окна, которое отсчитывается в часовом поясе `tz`. Временное окно применяется, если час или минута его начала или конца не равны нулю; если все четыре значения равны нулю, ограничения по времени нет. Визит вне расписания блокируется с причиной `14`.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `id` | Числовой идентификатор кампании. |
| `api` | Ссылка на API-функцию проверки визитов по этой кампании. |

Коды ошибок:

- `scope` - пространство не определено или у вас нет прав на него (см. [Пространства](#filterscopes)).
- `no-site` - кампания с указанным `uid` не найдена в текущем пространстве.
- `no-domain` - не указан ни идентификатор кампании, ни домен или название кампании.
- `user-required` - нужно создать новую кампанию, но параметр `user` не передан (пространства команды и администратора).
- `db` - произошла системная ошибка работы с базой данных.

```json

    "status": "ok",
    "id": 4567,
    "api": "https://domain.com/fltr/123-654b807372f614e64b9-4567"
}
```

    "error": "no-domain"

## Список кампаний

**URL вебмастера**: `https://domain.com/api/filter/list.json?id={token}`

**URL команды**: `https://domain.com/api/filter/list.json?id={token}&scope=gang`

Функция возвращает список кампаний, которые созданы в разделе фильтрации трафика. В пространстве команды она возвращает кампании всех участников команды, в пространстве администратора - кампании всех пользователей (см. [Пространства](#filterscopes)). У функции нет собственных параметров фильтрации; список ограничивается только параметрами выбора пространства:

| Поле | Описание |
| --- | --- |
| `user` | Пространство команды: вернуть только кампании этого участника команды. Пространство администратора: вернуть только кампании этого пользователя. |
| `gang` | Только для пространства администратора: вернуть только кампании участников этой команды. |

Результатом выполнения функции является список ассоциативных массивов со следующими полями (пустой список - `[]`):

| Поле | Описание |
| --- | --- |
| `id` | Идентификатор кампании фильтрации. |
| `user` | Идентификатор владельца кампании. |
| `api` | Ссылка API для проверки визитов по этой кампании. Содержит API-ключ владельца кампании. |

Поля в массиве статистики кампании (счётчики - итоги по кампании, цифры из журнала визитов см. в [Статистике визитов](#filterstats)):

- `click` - общее количество визитов.
- `black` - количество целевых визитов.
- `white` - количество заблокированных визитов.
- `leads` - общее количество лидов.
- `approve` - количество подтверждённых лидов.
- `cancel` - количество отклонённых лидов.
- `cash` - общая сумма заработка, округлённая до двух знаков.
- `cr` - конверсия по целевым визитам, проценты, два знака после запятой.
- `epc` - заработок на целевой визит, два знака после запятой. Перед делением заработок округляется вниз до целого числа.
- `appr` - процент аппрува, проценты, два знака после запятой.

Функция возвращает данные кампании фильтрации. Если передан идентификатор кампании в поле `uid`, функция будет извлекать кампанию по этому идентификатору. | Поле | Описание |

| `domain` | Домен или название кампании фильтрации (используйте уникальные имена). |

**URL команды**: `https://domain.com/api/filter/block.json?id={token}&list={list}&ip={ip}&scope=gang`

**URL администратора**: `https://domain.com/api/filter/block.json?id={token}&list={list}&ip={ip}&scope=admin`

Функция добавляет одну запись в выбранный чёрный список. Может блокировать как IP-адреса и диапазоны, так и заголовки. Вид записи определяется видом списка (IP-адреса, IP-подсети, IPv6-адреса или заголовки), а не параметрами. Доступные для изменения списки зависят от [пространства](#filterscopes): в пространстве вебмастера это ваши персональные списки, в пространстве команды - списки вашей команды и персональные списки участника, переданного в `user`, в пространстве администратора - любой список (или списки переданных `user` или `gang`). Недоступный список возвращает `bad-list`. Содержимое полей и используемые идентификаторы описаны в [документации по чёрным спискам](blacklist.md).

Сами чёрные списки создаются, настраиваются и очищаются с помощью [API чёрных списков](api-blacklist.md); его функция [Добавление записи](api-blacklist.md#blacklistblock) предлагает больше возможностей (срок действия записи, обновление существующей записи). Записи, добавленные этой функцией, не имеют срока действия; запись, которая уже есть в списке, возвращает `failed`. Поиск по IPv4-подсетям кэшируется примерно на 11 минут для каждого блока /24, поэтому новая подсеть может начать действовать для недавно проверенных адресов только спустя это время.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `list`* | Обязательный параметр. Идентификатор чёрного списка. |
| `ip` | IP-адрес или адрес подсети, которую необходимо заблокировать: IPv4 для списков IP-адресов и IP-подсетей, IPv6 для списков IPv6-адресов. Обязателен для этих видов списков. Частные и зарезервированные адреса отклоняются (`bad-ip`). |
| `size` | Размер подсети для блокировки (рекомендуется 24 для IPv4 и 64 для IPv6). Обязателен для списков подсетей: от 8 до 31 для IPv4, от 32 до 128 для IPv6. Адрес округляется вниз до начала подсети. |
| `value` | Содержимое заголовка для блокировки. Обязателен для списков заголовков: текст или регулярное выражение, до 250 символов, UTF-8. |
| `regexp` | Использовать проверку по регулярному выражению вместо поиска подстроки, 0 или 1. Выражение не проверяется при сохранении, некорректное выражение пропускается при фильтрации. |
| `white` | Только для списков заголовков: создать белое правило, 0 или 1. Визит блокируется, если заголовок **не** совпадает с `value` или вообще не передан. По умолчанию правило чёрное: визит блокируется, если заголовок совпадает. |
| `type` | Тип заголовка для блокировки, обязателен для списков заголовков: ID заголовка от 1 до 255 (см. [Идентификаторы заголовков](api-blacklist.md#blacklistheaders)). Правило с неизвестным ID сохраняется, но никогда не срабатывает. |
| `comment` | Комментарий к заблокированной сущности: число (см. [Коды причин](api-blacklist.md#blacklistcomments) в API чёрных списков). |
| `user`, `gang` | Параметры выбора пространства, см. [Пространства](#filterscopes). |

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `id` | Идентификатор добавленной записи. |
| `ip` | Списки IP-адресов: адрес в том виде, в котором он был передан. Списки IP-подсетей: первый адрес подсети в виде целого числа. Списки IPv6: первый адрес подсети в виде строки. Для списков заголовков не возвращается. |
| `size` | Только для списков подсетей: размер подсети. |
| `value` | Только для списков заголовков: содержимое заголовка. |
| `type` | Только для списков заголовков: ID заголовка. |
| `regexp` | Только для списков заголовков: признак регулярного выражения (логическое значение). |
| `white` | Только для списков заголовков: признак белого правила (логическое значение). |

Коды ошибок:

- `scope` - пространство не определено или у вас нет прав на него (см. [Пространства](#filterscopes)).
- `no-list` - параметр `list` не передан или равен 0.
- `bad-list` - чёрный список не найден или недоступен в текущем пространстве.
- `bad-ip` - IP-адрес невалидный, частный или зарезервированный.
- `bad-size` - некорректный размер подсети.
- `bad-type` - некорректный тип блокируемого заголовка (не число от 1 до 255).
- `bad-value` - некорректное содержимое заголовка для блокировки (пустое, длиннее 250 символов или не в UTF-8).
- `failed` - запись не удалось сохранить, например, она уже есть в списке.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "id": 1234567,
    "ip": "12.34.56.78"
}
```

**Пример успешного ответа сервера для списка заголовков:**

```json
{
    "status": "ok",
    "id": 77,
    "value": "HeadlessChrome",
    "type": 1,
    "regexp": false,
    "white": false
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "bad-list"
}
```

<a id="filterpostback"></a>
## Отправить постбек в мини-трекер

**URL**: `https://domain.com/api/filter/postback.json?id={token}&uid={uid}&status={status}`

Функция отвечает за обслуживание [встроеного мини-трекера](tracker.md). Она увеличивает счётчик лидов в статусе ожидание, аппрув и отмена, а также наращивает сумму заработка. Не поддерживает какую-либо дедупликацию событий.

Функция не использует [пространства](#filterscopes): она работает только с кампаниями владельца ключа (ключ администратора может действовать от имени другого пользователя с помощью параметра `uu`), а параметр `scope` не влияет на её работу.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `uid` | Идентификатор кампании фильтрации (обязательный параметр). |
| `payout` | Сумма выплаты для подтверждённого лида. В качестве десятичного разделителя допускается запятая; отрицательное значение уменьшает заработок. |
| `status` | Статус лида (обязательный параметр, см. ниже) |

Статусы лида:

- **Новый** - `lead`, `wait`, `process`, `hold`, `new`
- **Подтверждён** - `approve`, `sale`, `approved`, `confirm`, `confirmed`
- **Отклонён** - `cancel`, `trash`, `cancelled`, `reject`, `fake`

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `filter` | Идентификатор кампании фильтрации. |

Коды ошибок:

- `no-id` - не указан ID кампании фильтрации.
- `bad-id` - некорректный ID кампании фильтрации: кампания не найдена или принадлежит другому пользователю.
- `bad-status` - не удалось распознать статус.

**Пример успешного ответа сервера:**

```json
{
    "status": "ok",
    "filter": 4567
}
```

**Пример ошибочного ответа сервера:**

```json
{
    "status": "error",
    "error": "bad-status"
}
```

<a id="filterlog"></a>
## Журнал визитов

**URL вебмастера**: `https://domain.com/api/filter/log.json?id={token}`

**URL команды**: `https://domain.com/api/filter/log.json?id={token}&scope=gang`

**URL администратора**: `https://domain.com/api/filter/log.json?id={token}&scope=admin`

Функция возвращает одну страницу журнала визитов кампаний фильтрации, сначала самые новые визиты. Запись описывает один проверенный визит: результат проверки, чёрный список, который его заблокировал, страну, IP-адрес, данные об устройстве, User-Agent, найденные IP-адреса и перехваченные заголовки запроса. Записи ограничены [пространством](#filterscopes) запроса: ваши собственные визиты, визиты участников вашей команды или, для администратора, все визиты.

Функция только читает журнал: она не выполняет проверок и не изменяет счётчики. Визит появляется в журнале с задержкой, после фоновой обработки журнала. Визит не записывается, если кампания находится на паузе или выключена либо если он исключён режимом журнала кампании (`log`, см. [Настройка кампании](#filterset)). Визиты, которые проверяет поток, привязанный к кампании, также записываются в журнал, но не добавляются к счётчикам кампании в [Списке кампаний](#filterlist). Поэтому число записей может отличаться от счётчиков кампании.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `page` | Номер страницы, по умолчанию 1. |
| `show` | Количество записей на странице, по умолчанию 50, максимум 1000. |
| `site` | Показать только визиты этой кампании (идентификатор). |
| `list` | Показать только визиты, заблокированные этим чёрным списком (идентификатор). |
| `result` | Фильтр по результату проверки (см. ниже). |
| `ip` | Показать только визиты с этого IP-адреса (IPv4 или IPv6). Некорректный адрес игнорируется. |
| `ua32` | Показать только визиты с этим User-Agent: значение `ua32` из записи. Значение `0` игнорируется. |
| `geo` | Показать только визиты из этой страны, двухбуквенный код. |
| `user`, `gang` | Параметры выбора пространства, см. [Пространства](#filterscopes). |

Значения фильтра `result`:

- `-2` - только разрешённые визиты (показан целевой сайт, результат `0`).
- `-1` - только заблокированные визиты (любой ненулевой результат).
- `0`..`14` - точно этот [код результата проверки](#filterreasons).

Некорректные значения фильтров игнорируются. Фильтры `ip` и `ua32` сравнивают 32-битные хэши, поэтому совпадение не гарантирует точный адрес или User-Agent (разные IPv6-адреса могут совпадать).

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `data` | Записи страницы: объект, ключи которого - идентификаторы записей, сначала самые новые (пустая страница - пустой массив). Поля записи описаны ниже. |
| `nav` | Постраничная навигация: `total` - число записей, подходящих под фильтры, `page` - текущая страница, `pages` - число страниц, `show` - размер страницы. Страница за последней возвращает пустой `data`. |

Коды ошибок:

- `scope` - пространство не определено или у вас нет прав на него (см. [Пространства](#filterscopes)).

Поля записи `data`:

| Поле | Описание |
| --- | --- |
| `id` | Идентификатор записи. |
| `user` | Идентификатор владельца кампании. |
| `site` | Идентификатор кампании. |
| `time` | Время визита, Unix timestamp. |
| `result` | Код результата проверки от 0 до 14 (см. [коды результата проверки](#filterreasons)); `0` - показан целевой сайт. |
| `list` | Идентификатор чёрного списка, который заблокировал визит, `0`, если такого нет. |
| `geo` | Двухбуквенный код страны в нижнем регистре, `zz`, если страна не определена. |
| `ip` | IP-адрес посетителя (IPv4 или IPv6). |
| `mobile` | `true` для мобильного User-Agent. |
| `os` | ID операционной системы (см. [настройку кампании](#filterset)), `0` - не определена. |
| `browser` | ID браузера (см. [настройку кампании](#filterset)), `0` - не определён, `11` - бот. |
| `ua` | User-Agent посетителя. |
| `ua32` | 32-битный хэш (CRC32) User-Agent, может использоваться в фильтре `ua32`. |
| `ips` | IP-адреса, найденные в заголовках запроса (массив). |
| `headers` | Перехваченные заголовки запроса: объект `{ "название заголовка": "значение" }` без User-Agent. Если у заголовка нет известного названия, ключом служит его числовой ID. |

Срок хранения: по умолчанию записи хранятся 90 дней, а исходные данные (`ua`, `ips`, `headers`) - 30 дней. После этого запись остаётся в журнале, но `ua` становится пустой строкой, а `ips` и `headers` - пустыми массивами.

<a id="filterstats"></a>
## Статистика визитов

**URL вебмастера**: `https://domain.com/api/filter/stats.json?id={token}&item=date`

**URL команды**: `https://domain.com/api/filter/stats.json?id={token}&item=date&scope=gang`

**URL администратора**: `https://domain.com/api/filter/stats.json?id={token}&item=date&scope=admin`

Функция возвращает статистику проверенных визитов, сгруппированную по дням или по кампаниям за выбранный период: общее число визитов, число целевых ("black") и заглушечных ("white") визитов и распределение причин блокировки в процентах. Кампании ограничены [пространством](#filterscopes) запроса.

Статистика рассчитывается по [журналу визитов](#filterlog), поэтому действуют те же ограничения: визиты, исключённые режимом журнала кампании, отсутствуют, а данные доступны в течение срока хранения журнала (по умолчанию 90 дней). Поэтому числа могут отличаться от счётчиков кампании в [Списке кампаний](#filterlist): они накопительные, учитывают также визиты кампаний на паузе и выключенных кампаний и не включают проверки потоков.

Функция может принимать на вход следующие параметры:

| Поле | Описание |
| --- | --- |
| `item`* | Обязательный параметр. Группировка: `date` - одна строка на календарный день, `site` - одна строка на кампанию. |
| `from` | Первый день периода в формате `YYYY-MM-DD`. По умолчанию на 6 дней раньше `to` (период 7 дней). Если он позже `to`, заменяется на `to`. |
| `to` | Последний день периода (включительно) в формате `YYYY-MM-DD`. По умолчанию сегодня; более поздняя дата заменяется на сегодняшнюю. |
| `site` | Считать только визиты этой кампании (идентификатор). |
| `page` | Номер страницы строк, по умолчанию 1. |
| `show` | Количество строк на странице, по умолчанию 50, максимум 1000. |
| `user`, `gang` | Параметры выбора пространства, см. [Пространства](#filterscopes). |

Дни считаются по часовому поясу сервера. Длина периода не ограничена.

Результатом выполнения функции является ассоциативный массив:

| Поле | Описание |
| --- | --- |
| `status` | Результат выполнения операции: `ok` в случае успешного выполнения, `error` в случае ошибки. |
| `error` | Код ошибки для статуса `error` (см. ниже) |
| `data` | Строки страницы: объект, ключи которого - идентификаторы строк (`id`). При `item=date` строки идут от самого нового дня к самому старому, при `item=site` - в алфавитном порядке названий кампаний. Дни и кампании без визитов за период отсутствуют. Пустая страница - пустой массив. Поля строки описаны ниже. |
| `nav` | Постраничная навигация, как в [Журнале визитов](#filterlog); `total` - число строк (дней или кампаний). |
| `dataset` | Справочные данные: `results` - объект с названиями кодов результата проверки `0`..`14` на языке аккаунта пользователя. |

Коды ошибок:

- `scope` - пространство не определено или у вас нет прав на него (см. [Пространства](#filterscopes)).
- `no-item` - не передан параметр `item`.
- `bad-item` - `item` не равен ни `date`, ни `site`.
- `bad-from` - `from` не является корректной датой в формате `YYYY-MM-DD`.
- `bad-to` - `to` не является корректной датой в формате `YYYY-MM-DD`.

Поля строки `data`:

| Поле | Описание |
| --- | --- |
| `id` | При `item=date`: день в виде целого числа `YYYYMMDD`. При `item=site`: идентификатор кампании. |
| `name` | При `item=date`: день в формате `YYYY-MM-DD`. При `item=site`: название кампании (`ID <id>`, если кампания не найдена или недоступна в пространстве). |
| `user` | Только при `item=site`: идентификатор владельца кампании (`0`, если кампания не найдена). |
| `click` | Общее число записанных визитов. |
| `black` | Число целевых визитов (результат `0`). |
| `black_pct` | Доля целевых визитов в `click`, проценты, один знак после запятой. |
| `white` | Число заблокированных визитов (любой ненулевой результат). |
| `white_pct` | Доля заблокированных визитов в `click`, проценты, один знак после запятой. |
| `reason` | Объект: число визитов по каждому коду результата проверки от `1` до `14` (все ключи присутствуют, ноль, если таких визитов не было). |
| `reason_pct` | Объект с теми же ключами: доля каждого кода в `click`, проценты, один знак после запятой. |
